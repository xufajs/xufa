Overview Guide Reference

Reference

Authentication with no dependencies: scrypt passwords, JSON Web Tokens with rotating keys, TOTP, login lockout, rotating refresh tokens, API keys, HTTP Basic, Passport strategies and a plugin for @xufa/http. Every declaration of its TypeScript declarations (packages/auth/index.d.ts), as they are written, with their comments: made from them each time the docs are built. How to use them is in the overview.

A key, with its algorithm; an encrypted private key in PEM with its passphrase.

AuthRule

export type AuthRule<User = any> =
  true | string | string[] | ((user: User, request: any) => boolean | Promise<boolean>) | AuthRuleOf<User>;

A check of a route: an authenticated user, a role, roles (any of them), a function of the user, or which strategies may identify the user (with roles or a check).

AuthCheck

type AuthCheck<User> = (user: User, request: any) => boolean | Promise<boolean>;

TenantRule

export type TenantRule = true | '*';

The tenant of a route: true, a user of the tenant of the request; '*', a user of every tenant.

AuthRuleOf

export type AuthRuleOf<User = any> =
  | { strategy: string | string[]; roles?: string | string[]; check?: AuthCheck<User>; tenant?: TenantRule }
  | { strategy?: string | string[]; roles: string | string[]; check?: AuthCheck<User>; tenant?: TenantRule }
  | { strategy?: string | string[]; roles?: string | string[]; check: AuthCheck<User>; tenant?: TenantRule }
  | { strategy?: string | string[]; roles?: string | string[]; check?: AuthCheck<User>; tenant: TenantRule };

Which strategies may identify the user (by name: the others are refused), any of some roles or a check, and the tenant the user must be of. One of them at least.

StrategyResult

export type StrategyResult<User = any> =
  | { user: User; info?: unknown }
  | { fail: { challenge?: string; message?: string; status?: number; error?: Error } }
  | null;

What a strategy finds in a request: a user, credentials that are not valid, or none of its kind (null).
