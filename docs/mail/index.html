Overview Reference

@xufa/mail

Emails as classes, as Laravel's Mailables: each says who it goes to and what it says (a template of @xufa/template with its data), and a Mailer renders it in a layout that email clients read and sends it, at once or from a job of @xufa/queue. Sending is creating an object of the model of the emails of the ORM (SMTP, or kept in memory in tests). And notifications: something that happened, told to the users it concerns by mail, kept in the database, or by channels of your own.

Quick start

import { Database, Model, fields } from '@xufa/orm';
import { Mailable, Mailer, mailFields } from '@xufa/mail';

class Email extends Model {
  static fields = mailFields(fields); // from, to, cc, bcc, replyTo, subject, text, html, attachments... and what was sent
}
// In production: { backend: 'smtp', url: 'smtp://user:password@smtp.example.com:587', from: ... }
new Database({ backend: 'memory-mail', from: 'Shop <shop@example.com>' }).register(Email);

class OrderShipped extends Mailable {
  constructor(order) {
    super();
    this.order = order; // the fields of a mailable are the data of its templates
  }

  envelope() {
    return { subject: 'Your order {{ order.number }} is on its way' };
  }

  content() {
    return {
      html: '<p>Hello {{ order.name }},</p><p>It arrives on {{ order.day }}.</p>{{> button ({ url: order.url, text: "Track it" }) }}',
      preheader: 'It arrives soon',
    };
  }
}

const mailer = new Mailer({ model: Email, app: { name: 'Shop', url: 'https://shop.example' } });
const order = { number: 'A-17', name: 'Ada', day: 'Friday', url: 'https://shop.example/track/A-17' };
const sent = await mailer.send(new OrderShipped(order), { to: 'Ada <ada@example.com>' });
console.log(sent.subject, sent.accepted);
console.log(sent.text);
Your order A-17 is on its way [ 'ada@example.com' ]
Hello Ada,

It arrives on Friday.

Track it (https://shop.example/track/A-17)

Mailables

A Mailable has three methods, each optional, and may be async:

  • envelope(): { subject, to, cc, bcc, replyTo, from, headers }. The subject is a template. The recipients given to send() (and its subject) go over these.
  • content(): { view } (the files name.html and name.txt of the views of the Mailer), or { html, text } (templates); with: their data, over the fields of the mailable, app and the globals of the Mailer; preheader, footer, layout.
  • attachments(): the files of the email (see Attachments).

A plain object is an email too: mailer.send({ to, subject, view, with, attachments }).

Content and layout

  • HTML templates escape their values; text templates (.txt, text, the subject) do not.
  • Without text, the text is made of the HTML (clients without HTML show it, and the filters of spam read both): blocks on lines of their own, links as text (address), lists with dashes.
  • The HTML goes in the layout of xufa: a column of 600 px in tables and inline styles, with the name of the app (app: { name, url }) above, the footer below, and the preheader (the line clients show after the subject) hidden at the top. layout: false (of the Mailer or of an email) sends the HTML as it is; a template of your own takes {{{ body }}}.
  • {{> button ({ url, text: 'Go' }) }} is a button that looks the same in every client. mailer.preview(mail) gives the HTML to look at.

Sending and queueing

const mailer = new Mailer({ model: Email, views: 'views/mail', app: { name: 'Shop' }, queue });

await mailer.send(new OrderShipped(order), { to: user.email }); // now: the object of the model, with what was sent
await mailer.queue(new OrderShipped(order), { to: user.email, delay: '5m', priority: 2 }); // from a worker
  • send() creates the object of the model of the emails, which sends it: its mailInfo fields say what the server answered (messageId, accepted, rejected, sentAt).
  • queue() renders the email now and enqueues a job (xufa:mail) that sends it, tried again when the server of mail fails (attempts, 5); options of the job: delay, at, priority, queue, key.
  • A model without a field the email has (an HTML email, a model without html) is an error, not a silence: mailFields(fields) has them all.

Attachments

attachments() {
  return [
    { path: 'invoices/F-9.pdf' }, // read when the email is rendered
    { filename: 'report.csv', content: csv, contentType: 'text/csv' },
    { filename: 'logo.png', content: logo, cid: 'logo' }, // <img src="cid:logo"> in the HTML
  ];
}

Queued, their bytes travel in the job as base64.

Notifications

A Notification says by which channels it goes (via(user)) and what each one gets: toMail(user) a Mailable (or a plain email), toDatabase(user) data to keep, and to<Channel>(user) for channels of your own. A Notifier sends it to each user by each channel, from a job each (one that fails is tried again alone), or at once. 

import { Notification, Notifier, notificationFields } from '@xufa/mail';

class InvoicePaid extends Notification {
  constructor(invoice) {
    super();
    this.invoice = invoice; // an object of a model: carried by its key, read again in the worker
  }

  via(user) {
    return user.wantsEmail ? ['mail', 'database'] : ['database'];
  }

  toMail() {
    return { subject: 'Invoice {{ invoice.number }} paid', view: 'invoice-paid' };
  }

  toDatabase() {
    return { invoice: this.invoice.number, amount: this.invoice.amount };
  }
}

const notifier = new Notifier({ mailer, queue, model: NotificationRecord, notifications: [InvoicePaid], models: [User, Invoice] });
await notifier.notify(user, new InvoicePaid(invoice)); // jobs: one for the mail, one for the database
await notifier.notify(admins, new InvoicePaid(invoice), { now: true }); // without the queue
  • By mail, a notification goes to user.routeNotificationFor('mail'), or to user.email.
  • With a queue, the classes of the notifications (notifications) and of the models they carry (models) are given to the Notifier, which makes them again in the workers: a notification carries its own fields as JSON, objects of models by their key (read again when the job runs), and dates.
  • Notifier.route('mail', 'billing@example.com') is someone who is not a user (and .route('sms', '+34...') for more channels).

Channels

const notifier = new Notifier({
  mailer,
  channels: { sms: (user, text) => sms.send(user.routeNotificationFor('sms') || user.phone, text) },
});
// A notification with via() => ['sms'] and toSms(user) => 'Your code is 123456'

Kept in the database

class NotificationRecord extends Model {
  static fields = notificationFields(fields); // notifiableType, notifiableId, type, data, readAt, createdAt
  static options = { table: 'notifications' };
}

const unread = await notifier.of(user, { unread: true }); // the newest first
await notifier.markRead(user); // all, or markRead(user, [keys])
