ORM

@xufa/orm (or xufa/orm) has models and QuerySets in the spirit of Django, on SQL and NoSQL databases, with no dependencies. The same models and queries run on every backend, and give the same results.

A quick tour

const { Database, Model, fields, or, F, Count, Sum } = require('@xufa/orm');

class Author extends Model {
  static fields = {
    name: fields.string({ maxLength: 100 }),
    email: fields.string({ null: true, unique: true }),
    createdAt: fields.datetime({ autoNowAdd: true }),
  };

  static options = { ordering: ['name'] };
}

class Book extends Model {
  static fields = {
    title: fields.string({ maxLength: 200 }),
    pages: fields.integer({ null: true, min: 1 }),
    author: fields.foreignKey(() => Author, { relatedName: 'books', onDelete: 'cascade' }),
  };
}

const db = new Database({ backend: 'sqlite', filename: 'app.db' });
db.register(Author, Book);
await db.connect();
await db.sync(); // creates the tables (or collections and indexes) that do not exist

const ada = await Author.objects.create({ name: 'Ada' });
await ada.books.create({ title: 'Notes', pages: 120 });

const books = await Book.objects
  .filter({ author__name__istartswith: 'a', pages__gte: 100 })
  .exclude(or({ title__contains: 'draft' }, { pages: null }))
  .selectRelated('author')
  .orderBy('-pages')
  .limit(10);
books[0].author.name; // 'Ada'

await Book.objects.filter({ author: ada }).update({ pages: F('pages').add(1) });
await Book.objects.values('author__name').annotate({ books: Count(), pages: Sum('pages') });

Models and options

A model is a class extending Model, with static fields and, optionally, static options:

OptionWhat it does
tableThe name of the table (the snake case of the class name by default). Dots are part of the name.
schemaThe schema of the table in PostgreSQL. SQLite names the table schema.table, MongoDB the collection.
orderingThe default order of its QuerySets: ['-createdAt', 'name'].
indexes[['a', 'b'], { fields: ['c'], unique: true }]. In SQL, condition makes a partial index: { fields: ['c'], unique: true, condition: '"deleted" IS NULL' }.
abstractA parent whose fields its children get; it has no table.
primaryKeyThe fields of a composite primary key, or false for a model without one (see Primary keys).
fillfactorPostgreSQL, 10 to 100: room left in the pages of the table for the new versions of updated rows. Updates of tables updated often get about twice as fast when they change no indexed column.
cachetrue or { ttl, indexes }: get() by key answered from a cache (see Caches).
databaseThe database of the model, with Databases.

Every field takes null, default (a value or a function), unique, index, primaryKey, choices, column and validate (functions that return a message, or false, when a value is not valid). In SQL databases a field can also say its column exactly: sqlType ('VARCHAR(255)') and dbDefault (a DEFAULT of the column).

datetime and date take PostgreSQL's infinite dates as Infinity and -Infinity (or those words as text), after and before every other date. SQLite keeps them as the texts infinity and -infinity, which sort the same way; MongoDB has none and refuses them.

Arrays, hstore, geometries

These fields are native types of PostgreSQL. The other backends store them too, as JSON text (SQLite) or documents (MongoDB), so the same models run everywhere. 

class Place extends Model {
  static fields = {
    tags: fields.array(fields.string({ maxLength: 20 })), // VARCHAR(20)[]
    attributes: fields.hstore({ null: true }), // HSTORE: { wifi: 'yes', seats: '40' }
    location: fields.geometry({ shape: 'POINT', srid: 4326 }), // GEOMETRY(POINT,4326)
    area: fields.geography({ shape: 'POLYGON', null: true }), // GEOGRAPHY(POLYGON)
  };
}

await Place.objects.create({
  tags: ['cafe', 'quiet'],
  attributes: { wifi: 'yes' },
  location: { type: 'Point', coordinates: [-3.7038, 40.4168], crs: { type: 'name', properties: { name: 'EPSG:4326' } } },
});
await Place.objects.filter({ tags: ['cafe', 'quiet'] }).count(); // arrays and maps are compared as wholes
  • Arrays, as Django's ArrayField: their items are checked by the field given (null items are kept). Arrays of hstore, JSON or ranges work too.
  • hstore, as Django's HStoreField: values are strings or nulls (numbers and booleans are taken as their text). The database needs the extension hstore.
  • Geometries of PostGIS are GeoJSON values; their SRID is their crs. They are written as EWKT and read back from PostGIS's EWKB. A value without a crs is stored without an SRID. Coordinates must be numbers: text that is not one is refused, not stored as 0. The database needs the extension postgis.

Relations

A foreign key author keeps the key in authorId and, once loaded (selectRelated, prefetchRelated, await book.load('author'), or assigned), the object in author. The model it points to gets the reverse relation, relatedName (<model>Set by default): author.books is a QuerySet, and author.books.create() sets the key.

Option of foreignKeyWhat it does
onDeletecascade (default), setNull, protect or doNothing, done by the ORM so that it is the same on every database
relatedNameThe name of the reverse relation
attnameThe name of the key (author_id)
toFieldA unique field of the other model to point to, instead of its primary key
dbOnDelete, dbOnUpdateON DELETE and ON UPDATE of the foreign key in SQL (cascade, setNull, restrict, noAction), for writes made outside the ORM
dbConstraint: falseNo constraint in the database at all

A many-to-many relation tags (of a Book to a Tag) goes through a model with a foreign key to each, made when the models are registered (or given as through). book.tags is the QuerySet of the tags of a book, with add(), remove(), set() and clear(); tag.books (its relatedName) is the other way. Both can be in conditions (Book.objects.filter({ tags__name: 'x' })) and in prefetchRelated.

Primary keys

A model without a primary key gets id. A key of several fields (primaryKey: true on each, or options.primaryKey: ['student', 'course']) is composite, as Django's CompositePrimaryKey: instance.pk is the array of their values, and pk in queries takes arrays (get({ pk: [1, 'math'] }), pk__in: [[1, 'math'], [2, 'logic']]). No foreign key can point to such a model, except to a unique field with toField; MongoDB does not support them.

options.primaryKey: false makes a model without a primary key, for tables that have none (logs, tables of other systems). Its rows are inserted, read, counted, updated and deleted with QuerySets, but its objects cannot be found again by themselves: save() of a saved one, delete() and refresh() throw.

Objects

  • save({ fields }): inserts or updates, validating first.
  • delete(), refresh(), load(name), pk.
  • validate(): throws a ValidationError with errors by field and the status code 400.
  • toJSON(): the values, with the relations loaded.
  • Hooks: Model.on('beforeSave' | 'afterSave' | 'beforeDelete' | 'afterDelete', fn).
  • Model.jsonSchema({ exclude, partial }): the JSON Schema of the objects, for the schemas of routes.

QuerySets

Model.objects is a lazy QuerySet. Refining it gives a new one; it runs when it is awaited or iterated (for await).

RefineRun
filter, exclude, orderBy, limit, offset, slice, only, values, valuesList, selectRelated, prefetchRelated, annotate, using, selectForUpdate, limitPer get, first, last, count, exists, aggregate, create, getOrCreate, updateOrCreate, bulkCreate, update, delete

limitPer(names, count, offset) gives the first objects of every group: Book.objects.orderBy('-pages').limitPer('author', 3) is the three longest books of each author, with a ROW_NUMBER() window in SQL.

Conditions

Conditions are those of Django: field__lookup, and relation__field to follow foreign keys (joins in SQL, $lookup in MongoDB), reverse and many-to-many relations (Author.objects.filter({ books__title__contains: 'x' }): each author once).

LookupsMeaning
exact, iexactEqual (case insensitive)
contains, icontains, startswith, istartswith, endswith, iendswithText, with %, _ and the characters of regular expressions as plain characters
like, ilikePatterns of SQL LIKE (%, _, \), with the same results in SQLite and MongoDB
gt, gte, lt, lte, in, range, isnullComparisons
 
const { Q, and, or, not, F, Raw } = require('@xufa/orm');

Book.objects.filter(or({ pages__gte: 500 }, { author__name: 'Ada' }));
Book.objects.filter(new Q({ pages__gte: 500 }).or({ author__name: 'Ada' })); // the same
Book.objects.exclude(not({ title__icontains: 'notes' }));
Book.objects.filter({ pages__gt: F('chapters').mul(10) }); // compare with another field
Book.objects.filter(Raw(`length(${Raw.TABLE}.title) > ?`, [10])); // SQL of your own (SQL databases)

The conditions of one filter() on a relation of many are of the same row; those of chained calls, of any. A null is not equal, greater or less than anything, and exclude() keeps the rows with nulls, as in Django.

Aggregates

const { Count, Sum, Avg, Min, Max, Raw } = require('@xufa/orm');

await Book.objects.aggregate({ books: Count(), pages: Avg('pages') });
await Book.objects.values('author__name').annotate({ books: Count(), longest: Max('pages') });
// Across reverse relations (SQL databases): LEFT JOINs.
await Author.objects.values('name').annotate({ books: Count('books'), pages: Sum('books__pages') });
// Fragments of SQL (SQL databases).
await Book.objects.aggregate({ long: Raw('SUM(CASE WHEN pages > 300 THEN 1 ELSE 0 END)') });

Count takes { distinct: true }. A sum of no values is null.

Writing in bulk

  • update(values) and delete() of a QuerySet write every row it matches, with F() for values from other fields: update({ views: F('views').add(1) }). delete() follows the onDelete of the relations.
  • bulkCreate(objects) inserts many rows. In PostgreSQL, 500 objects or more go through COPY (the option copyRows of the database changes that number; false: never).
  • As in Django, bulkCreate can ignore the rows that break a unique key ({ ignoreConflicts: true }), or update the rows there ({ updateConflicts: true, updateFields: ['name'], uniqueFields: ['code'] }): INSERT ... ON CONFLICT in SQL databases.

Transactions and locks

await db.transaction(async () => {
  const account = await Account.objects.selectForUpdate().get({ pk: 1 }); // FOR UPDATE (PostgreSQL)
  account.balance -= 100;
  await account.save();
  await db.transaction(async () => {
    // a savepoint
  });
}); // commits when the function ends; rolls back when it throws

The queries inside the function run in the transaction, wherever they are in your code. Nested transactions are savepoints. selectForUpdate({ skipLocked, noWait, mode: 'share' }) locks the rows read. MongoDB has transactions on replica sets and sharded clusters, without savepoints.

Migrations

As in Django: await db.makeMigrations({ dir: 'migrations' }) compares the models with the schema the migration files describe, and writes a file (0002_auto.js) with the operations between them: tables created and dropped, fields added, dropped and altered, indexes and the fillfactor. A field added gets its default in the rows that exist; one without null or a default is refused.

await db.migrate({ dir }) applies the files not applied yet, in order, each in a transaction where the database has them, and records them (xufa_migrations). db.showMigrations({ dir }) lists them. 

// migrations/0003_rename.js: written by hand
module.exports = {
  operations: [
    { op: 'renameColumn', table: 'book', from: 'name', to: 'title' },
    { op: 'sql', sql: 'CREATE INDEX book_title_trgm ON book USING gin (title gin_trgm_ops)' },
    { op: 'run', fn: async (db) => { /* a data migration */ } },
  ],
};

SQLite has no ALTER COLUMN: its tables are made again, with the foreign keys checked after. In MongoDB, migrations make collections and indexes, fill the fields added and unset those dropped.

Several databases

const { Databases } = require('@xufa/orm');

const dbs = new Databases(
  { default: { backend: 'postgres', url: process.env.DATABASE_URL }, events: { backend: 'mongodb', url: process.env.EVENTS_URL } },
  { routes: { Event: 'events' } }
);
dbs.register(Author, Book, Event);
await dbs.connect();
await dbs.migrate({ dir: 'migrations' }); // migrations/default, migrations/events
await dbs.transaction('default', async () => { /* ... */ });

A model goes to the database of its option database, or of its route, or to the default one. Model.objects.using(db) runs one QuerySet elsewhere. Relations between models of different databases are followed with more queries; a query cannot join them.

Tenants

const { Tenants } = require('@xufa/orm');

const tenants = new Tenants({
  models: [Author, Book],
  config: async (id) => ({ backend: 'postgres', url: `postgres://app@db:5432/tenant_${id}` }),
  setup: (db) => db.migrate({ dir: 'migrations' }),
  max: 100, // databases kept open
});

await tenants.run('acme', () => Book.objects.count()); // the books of acme

The database of a tenant is opened (and set up) the first time it is used. Code run in a tenant, including what it awaits, uses its database. With the HTTP plugin, each request runs in its tenant (see With @xufa/http).

Caches

A model with the option cache (true, or { ttl, indexes }) answers get() by its primary key, or by a unique field of indexes, from the cache of its database. Saving or deleting an object removes it; update() and delete() of QuerySets clear the model. Inside transactions the cache is neither read nor filled. Values are copied in and out.

CacheWhere
MemoryCache({ max, ttl })In the process: an LRU of max keys. The default.
SharedCache({ bus })One copy in the primary of a cluster, asked by the workers.
LocalCache({ bus })A copy in each process, with invalidations sent to the others: reads never leave the process.
 
const { bus } = require('@xufa/cluster');
const db = new Database({ backend: 'postgres', url, cache: new LocalCache({ bus, max: 50000 }) });

With @xufa/http

const orm = require('@xufa/orm');

app.register(orm.plugin, { database: db, migrate: { dir: 'migrations' } });
// or { database: db, sync: true }, or { tenants: { tenants, resolve: (request) => request.headers['x-tenant'] } }

The plugin connects the database when the app starts (migrating it when asked), gives it as app.db, and closes it with the app. A ValidationError is answered with 400 and the messages of each field (errors); get() of nothing with 404. With tenants, a request without one gets 400 (unless required: false), and one of a tenant that does not exist, 404.

TypeScript

The declarations type models from their fields. Give the model an interface of the same name, and use Model.query() for QuerySets of the model (TypeScript cannot type Model.objects by the class). 

import { Model, fields, type Fields } from '@xufa/orm';

const bookFields = { title: fields.string(), author: fields.foreignKey(() => Author) };
class Book extends Model {
  static fields = bookFields;
}
interface Book extends Fields<typeof bookFields> {}

const books: Book[] = await Book.query().filter({ author__name: 'Ada' }); // book.title, book.authorId, book.author

The same on every backend

Each backend compiles the description of a query to its database, and they give the same results:

  • Nulls are never equal, greater or less than anything, and sort first ascending and last descending.
  • contains, startswith and endswith are case sensitive everywhere (SQLite's LIKE is not, so they are compiled without it).
  • Unique fields allow many nulls (partial unique indexes in MongoDB).
  • JSON values, arrays and maps are compared as wholes.
  • A sum of no values is null; groups of a missing field and of a null are the same group.

What differs, as it does between the databases:

  • Transactions: MongoDB has them on replica sets and sharded clusters only, and has no savepoints.
  • Foreign keys are constraints in SQL; in MongoDB, a key can point to nothing.
  • The order of strings is the collation of the database.
  • Raw queries: db.backend.raw(sql, params) in SQL; db.backend.db is the @xufa/mongo database in MongoDB.

Not yet: ordering and values across reverse relations (conditions and aggregates follow them), generic relations, and a command line for migrations.
