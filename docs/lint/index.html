Overview Reference

@xufa/lint

A linter with ESLint's recommended rules and a formatter with prettier's output: ESLint 9.39.5's own code for the rules and prettier 3.9.9's for formatting, ported as they are, run on TypeScript's parser. The rules pass ESLint's tests; the formatter writes what prettier writes. Configs are ESLint's flat configs, in xufa.lint.config.js. xufa lints and formats itself with it.

Quick start

npm install --save-dev @xufa/lint typescript
// xufa.lint.config.js
import { configs, globals } from '@xufa/lint';

export default [
  { ignores: ['dist/**'] },
  configs.recommended,
  {
    languageOptions: { globals: { ...globals.node } },
    rules: { 'no-unused-vars': ['error', { argsIgnorePattern: '^_' }] },
  },
  { files: ['**/*.cjs'], languageOptions: { sourceType: 'commonjs' } },
];
npx xufa-lint            # the folder of the config
npx xufa-lint src --fix  # writes what rules fix

Configs

xufa.lint.config.js (or .mjs, .cjs) exports a list of objects, as ESLint's eslint.config.js does; it is found from the working folder up.

KeyWhat it is
filesGlobs of the files the object applies to (all, without it). A pattern of files adds its files to those linted: .js, .mjs and .cjs by default.
ignoresFiles the object does not apply to; alone in an object, files ignored everywhere (node_modules and .git always are). ! takes back.
languageOptionsecmaVersion ('latest'), sourceType ('module', 'script', 'commonjs'), globals, parserOptions.ecmaFeatures.jsx.
rules'off', 'warn', 'error' (or 0, 1, 2), or [severity, ...options].
linterOptionsnoInlineConfig, reportUnusedDisableDirectives.
settingsWhat rules read in context.settings.

The objects that apply to a file are merged in order: languageOptions and settings deeply, rules by rule (a rule given only a severity keeps the options before it). Globs are minimatch's: **, *, ?, {a,b}, [abc], and a final / for a folder. globals has the environments of the package globals: node, browser, commonjs, jest, vitest, mocha, worker, the ES versions...

Comments

// eslint-disable-next-line no-undef -- given by the page
render(app);
/* global ajax:readonly */
/* eslint no-console: off */

eslint-disable, eslint-enable, eslint-disable-line and eslint-disable-next-line (with -- reasons), /* global */, /* exported */ and /* eslint rule: setting */, as ESLint reads them. Comments that disable ESLint's other rules are not errors; one that disables nothing is a warning (reportUnusedDisableDirectives).

The command

OptionWhat it does
--fixWrites what rules fix (again until nothing changes, 10 times at most).
--format stylish|jsonESLint's outputs.
--config fileAnother config.
--max-warnings nFails with more warnings.
--quietErrors only.

The exit code is 0, 1 with errors (or too many warnings), and 2 when it cannot run.

Formatting

npx xufa-format           # lists the files that are not formatted (exit 1 when any is)
npx xufa-format --write   # formats them
// xufa.lint.config.js
export default [
  configs.recommended,
  { format: { singleQuote: true, trailingComma: 'es5', printWidth: 120, ignores: ['vendor/**'] } },
];

JavaScript, TypeScript, JSX, JSON and markdown are written as prettier 3.9.9 writes them: its printers, ported as they are, with its options (printWidth, singleQuote, semi, trailingComma...) in the format key of configs, merged as the rest. format.ignores are files never formatted; the ignores of all configs are not formatted either. JavaScript is formatted as prettier's Babel parser has it (the parentheses of /** @type */ casts stay); package.json as JSON.stringify writes it; the code blocks of markdown in JavaScript, TypeScript and JSON are formatted too. Not formatted: CSS, HTML, YAML and other languages (in files or in code blocks), and the embedded languages of JavaScript (css`...`).

On this repository it writes what prettier writes for each of its 3,222 files of JavaScript, TypeScript, JSON and markdown, and also when they are first printed otherwise (40 columns, other options); JSON5 and JSON with comments (.json5, .jsonc, .babelrc...) are formatted as prettier does too. It is faster than prettier in each language, and xufa-format --check on the whole repository 1.8 to 2 times as fast as prettier --check (benchmarks). format(text, { filepath, ...options }) formats from code.

The rules

The 60 of @eslint/js's recommended set: configs.recommended turns them all on. The 61st, no-unexpected-multiline, is left out, as with eslint-config-prettier: line breaks are the formatter's. Their options, messages, fixes and suggestions are ESLint's, since their code is. defineRule(id, rule) adds one of yours, written as ESLint's are (meta, create(context)).

From code

import { Linter, configs } from '@xufa/lint';

const linter = new Linter();
const messages = linter.verify('let a = 1;', configs.recommended, 'a.js');
// [{ ruleId: 'no-unused-vars', severity: 2, message: "'a' is assigned a value but never used.", line: 1, column: 5, ... }]
const { output } = linter.verifyAndFix('if (!!a) b();', configs.recommended, 'a.js'); // 'if (a) b();'

loadConfig(file) and lintFiles(paths, configs, { fix }) do what the command does; parse(text) gives the ESTree of a file.

How it works

The formatter (lib/prettier) is prettier's printers of ESTree and markdown, its comments and its doc printer, made @xufa/lint's own code and tuned since. JavaScript and TypeScript are read by its own copy of TypeScript's parser (lib/prettier/parse/typescript.cjs, what the parser needs of TypeScript, loaded only for them) and converted to ESTree as typescript-estree does; JSON by a parser of its own, into the tree prettier's json parsers make; markdown by micromark. It is loaded as one ES module (lib/prettier/dist/format.mjs, built by @xufa/bundle).

The parser is @xufa/lint's: TypeScript's parser, its tree made the ESTree that espree makes for ESLint, with espree's tokens and comments. The rest is ESLint's code for the JavaScript language, ported to lib/eslint: scope analysis (eslint-scope), globals, the traversal with its selectors (esquery) and code path events, the reports of rules, disable directives and fixes. tools/port-lint ports it again from a checkout of ESLint; NOTICE.md has the licenses.

How it is checked

  • ESLint's tests of the 60 rules: 5,249 pass; 32 need another parser (typescript-eslint's).
  • The parser against espree: the same tree, tokens and comments for the 2,405 files of this repository and the 5,248 pieces of code of those tests.
  • Against ESLint on 2,425 files with problems (the ported tests of this repository): the same 40,779 problems, in about two thirds of the time.
  • The formatter against prettier: the same output for the 3,222 files of JavaScript, TypeScript, JSON and markdown of this repository, also when they are first printed otherwise (40 columns, other options); and for 27 cases of JSON, JSON5 and JSON with comments in five kinds of files with three sets of options.

Coming from ESLint

eslint.config.js becomes xufa.lint.config.js, with import { configs, globals } from '@xufa/lint' for @eslint/js and the package globals. Not there: ESLint's other rules (configuring one is an error that says so), plugins (but rules of yours), processors, caching, and TypeScript files.
