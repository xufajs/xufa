Overview Reference

@xufa/xlsx

Workbooks of Excel with no dependencies: readXlsx() gives the values of every sheet, writeXlsx() writes sheets of values with styles, merged cells and widths, and patchXlsx() sets some cells of a workbook people keep editing and leaves the rest as it was. It is what @xufa/rules reads its books with, and what exports to Excel are made with.

Quick start

npm install @xufa/xlsx
import { readXlsx, writeXlsx } from '@xufa/xlsx'; // or from 'xufa/xlsx'

const header = { bold: true, fill: 'DDEBF7', border: 'thin', align: 'center' };
const bytes = writeXlsx({
  sheets: [
    {
      name: 'Books',
      rows: [
        [{ value: 'Title', style: header }, { value: 'Pages', style: header }, { value: 'Read', style: header }],
        ['Dune', 412, new Date(Date.UTC(2026, 9, 1))],
        ['Solaris', 204, null],
      ],
      widths: [30],
      defaultWidth: 12,
    },
  ],
});
const [books] = readXlsx(bytes).sheets;
console.log(books.name, books.rows);
Books [
  [ 'Title', 'Pages', 'Read' ],
  [ 'Dune', 412, 2026-10-01T00:00:00.000Z ],
  [ 'Solaris', 204, null ]
]

Reading

readXlsx(bytes) gives { sheets: [{ name, rows, merges }] }, the sheets in their order: rows of cells from A1, null where empty, and values as Excel shows them: texts (shared, inline or rich), numbers, booleans, dates (numbers of a date format, as Date, of the 1900 or 1904 system), the last result of formulas, and errors as their text (#N/A). merges are the merged ranges, { top, left, bottom, right } from 0.

Writing

writeXlsx({ sheets }) gives the bytes of a workbook (a Buffer). A sheet has a name (31 characters at most, without \ / ? * [ ] :, one of its kind in the workbook), rows of cells, merges, widths of its columns in characters, and a defaultWidth for the rest. A cell is a value (a text, a number, a boolean, a date or null) or { value, style }. The same values give the same bytes.

Styles

A style is an object of bold, italic, underline, size, font, color and fill (RGB hex: '1F4E78', '#1F4E78'), border (true is thin; or medium, thick, dashed, dotted, double, hair; or one by side, { top, right, bottom, left }), align (left, center, right, fill, justify), valign (top, middle, bottom), wrap, and format: a code of numbers ('0.00%', 'yyyy-mm-dd') or the id of a built-in one. Dates take yyyy-mm-dd unless they have one. Each style is written once, whatever the cells that use it. 'title', 'header' and 'value' are the looks of the tables of @xufa/rules. 

const bytes = writeXlsx({
  sheets: [
    {
      name: 'Report',
      rows: [
        [{ value: 'Sales by quarter', style: { bold: true, size: 14 } }],
        ['Q1', { value: 0.125, style: { format: '0.0%' } }, { value: 'done', style: { color: '#008000', align: 'right' } }],
      ],
      merges: [{ top: 0, left: 0, bottom: 0, right: 2 }],
    },
  ],
});
const styles = unzip(bytes).get('xl/styles.xml').toString();
console.log(styles.match(/<numFmt [^>]*>/)[0]);
console.log(readXlsx(bytes).sheets[0].merges);
<numFmt numFmtId="164" formatCode="0.0%"/>
[ { top: 0, left: 0, bottom: 0, right: 2 } ]

Patching

A workbook people keep editing is changed in place: patchXlsx(bytes, sheet, { C7: 0.5 }) (or a Map) sets those cells and nothing else; its styles, other sheets, formats, comments and drawings are kept. A cell keeps its style. A merged range whose cells get different values is split (with whole, the values of the whole area they are of, which tells which merges are cut). A cell that loses its formula takes the calculation chain with it, and Excel rebuilds it. 

const original = writeXlsx({
  sheets: [
    { name: 'Prices', rows: [[{ value: 'Plan', style: 'header' }, { value: 'Price', style: 'header' }], ['basic', 10]] },
    { name: 'Notes', rows: [['kept as it was']] },
  ],
});
const patched = patchXlsx(original, 'Prices', { B2: 12, A3: 'gold', B3: 25 });
console.log(readXlsx(patched).sheets.map((sheet) => sheet.rows));
[
  [ [ 'Plan', 'Price' ], [ 'basic', 12 ], [ 'gold', 25 ] ],
  [ [ 'kept as it was' ] ]
]

Zip and references

The bytes of an .xlsx are a zip: unzip(bytes) gives its files (name to Buffer), and zip([[name, bytes or text], ...]) makes one, deflated, with a fixed date so the same entries give the same bytes. Both with node:zlib only. cellAt('C7') is { row: 6, column: 2 }, refOf(6, 2) is 'C7', columnName(27) is 'AB', and excelDate(serial) the date of a serial number of Excel.

Errors

An XlsxError (code: 'XUFA_XLSX_ERR') says what is wrong: bytes that are not a workbook, a sheet that is not there, a name of a sheet, a style, a color or a border Excel would not take. Bytes that are not a zip are a ZipError (XUFA_XLSX_ERR_ZIP, an XlsxError too). @xufa/rules gives them as its own RulesError (XUFA_RULES_ERR_XLSX, XUFA_RULES_ERR_ZIP).
