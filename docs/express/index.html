Overview Reference

@xufa/express

Express 5's API on @xufa/http, implemented anew with no dependencies: its own code, written to Express 5.2.1's behaviour and checked by Express's own tests, with @xufa/router finding the route of each request. An app of Express runs as it is, with all of Express's API and its types.

Quick start

npm install @xufa/express
import express from '@xufa/express'; // or require('@xufa/express')

const app = express();
const router = express.Router();

router.get('/books/:id', async (req, res) => {
  const book = await books.find(req.params.id);
  if (!book) return res.status(404).send('Not found');
  return res.json(book);
});

app.use(express.json({ limit: '1mb' }));
app.use('/api', router);
app.listen(3000);

Checked

  • Express's own tests: its 1,238 tests pass, every request routed by @xufa/router.
  • Against Express: the same apps built on Express 5.2.1 and on @xufa/express, the same requests sent to both (routes in every order, routers mounted on paths with params, sub-apps, all(), route(), param(), wildcards and optional parts, strict and case-sensitive routers, middlewares that change the url or the method, OPTIONS and HEAD), the same status, headers and body.

How it routes

Every route of the app's routers whose path @xufa/router can match (static parts and :params) is one of its routes, with a plan made once: for each router on the way, the layers that can meet its urls. Each router tries only those; the rest (not found, wildcards, a request whose url or method a layer changed) goes through every layer, as in Express. Against Express 5.2.1 on the same app (bench/express.js): 1.32–1.49x the requests a second on small routes, 1.85x on static files, 1.15x on large JSON, 1.14x on not found, and 4.2x on the last router of a large app (40 routers on /api), where Express tries every layer before.

What it adds

  • express({ server }): options of @xufa/http for its instance.
  • app.server(options): that instance, not listening (ready(), inject()).
  • app.register(plugin, options): a plugin of @xufa/http with routes of its own (the explorer of @xufa/openapi).

What differs

  • Charsets of bodies: those of the WHATWG Encoding standard, latin-1 and utf-16 (iconv-lite's others are 415).
  • No DEBUG traces nor deprecation warnings.
  • req.query is parsed once for each url (the same object until req.url changes).
  • Requests and responses of other classes (inject's) keep their prototype, with Express's members on one between.

Tests and tools

tools/port-express/port.js ports Express's tests (mocha's made @xufa/test's) from a checkout of Express; mime.js writes the table of mime-db.
