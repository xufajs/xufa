@xufa/client

A client of HTTP APIs on the fetch of Node.js, with no dependencies: base URLs, query strings and JSON, answers parsed, timeouts, retries with backoff, errors by status, hooks and logs. Bound to a request of @xufa/http, a call is cancelled when the client of that request goes away.

Quick start

npm install @xufa/client
const { createClient } = require('@xufa/client');

const books = createClient({ baseUrl: 'https://api.example.com/v1', headers: { authorization: `Bearer ${token}` } });
const list = await books.get('/books', { query: { author: 'ada', tags: ['sf', 'classic'] } });
const created = await books.post('/books', { json: { title: 'Dune' } });

Calls

  • get, head, options, post, put, patch, delete, request(method, path, options): the body of the answer (JSON by its content-type, text otherwise; nothing for 204 and HEAD).
  • baseUrl (its path kept), headers, query (arrays repeat the key), json or body, timeout (30 s for each attempt).
  • responseType: auto, json, text, buffer, stream, response; resolveBodyOnly: false gives { status, headers, body, url }; throwHttpErrors: false.
  • hooks: beforeRequest(call) and afterResponse(response, call). extend(options) makes a client with more options.
  • dispatcher: a dispatcher of undici for proxies; on Node.js 24, NODE_USE_ENV_PROXY=1.

Retries

3 attempts by default, for the idempotent methods and the statuses that may pass (408, 413, 429, 500, 502, 503, 504...), timeouts and failed connections. The waits grow with jitter (delay, factor, maxDelay), or are what Retry-After asks. retry: false, a number of attempts, or { attempts, methods, statuses, ... }.

In a request

app.get('/shelf', async (request) => books.for(request).get('/books'));

client.for(request): request.signal cancels the call and its retries when the browser leaves (the API called sees its connection closed), request.log logs it (outgoing request, incoming response with its status and ms, retries), and request.id goes in x-request-id.

retry()

const job = await retry(() => api.get(`/jobs/${id}`), { until: (job) => job.state === 'done', attempts: 20, delay: 500 });

Calls again until a result is accepted (RetryError with the last one otherwise), or an error is not retried (retryOn). A signal stops the waits.

Errors

HTTPError (status, headers, body parsed), TimeoutError, RequestError (cause), with method and url; a cancelled call throws the reason of its signal.

Faults (tests of resilience)

client.faults (of @xufa/faults) makes calls fail, wait, hang or get a status without reaching the API; the clients of extend() and for() share them. 

payments.faults.fail({ operations: 'write', paths: '/charges', rate: 0.2 }); // as a refused connection
payments.faults.respond({ status: 503, headers: { 'retry-after': '1' }, json: { error: 'busy' }, times: 2 });
payments.faults.hang({ operations: 'read' }); // the timeout of the call ends it: a TimeoutError
  • Operations: the methods (read, write); filters urls and paths: prefixes or regular expressions.
  • fail and down are failed connections (a RequestError, code ECONNREFUSED in its cause), retried as such; respond({ status, headers, json | body }) answers without the call.
  • Each attempt goes through the faults: times: 2 with 3 attempts fails twice, and the third reaches the API.
