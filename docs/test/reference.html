Reference

A very fast, zero-dependency test runner with a Jest/Vitest compatible API. Every declaration of its TypeScript declarations (packages/test/index.d.ts or index.d.cts), as they are written, with their comments: made from them each time the docs are built. How to use them is in the overview.

Shape

export type Shape<T> =
  IsNever<T> extends true
    ? { kind: 'never' }
    : IsAny<T> extends true
      ? { kind: 'any' }
      : IsUnknown<T> extends true
        ? { kind: 'unknown' }
        : T extends string | number | boolean | bigint | symbol | null | undefined | void
          ? { kind: 'primitive'; type: T }
          : T extends abstract new (...args: infer P) => infer I
            ? { kind: 'constructor'; params: Shape<P>; instance: Shape<I> }
            : T extends (...args: infer P) => infer R
              ? { kind: 'function'; params: Shape<P>; result: Shape<R>; this: Shape<ThisParameterType<T>> }
              : T extends readonly any[]
                ? { kind: 'array'; readonly: T extends any[] ? false : true; items: { [K in keyof T]: Shape<T[K]> } }
                : {
                    kind: 'object';
                    members: { [K in keyof T]-?: Shape<T[K]> };
                    optional: OptionalKeys<T>;
                    readonly: ReadonlyKeys<T>;
                  };

What a type is made of, in one form: two types that are the same in it have the same members (each of the same type, with the same optional and readonly keys), parameters, results and items, whatever their names (an interface and the object type of its members; an intersection and the object it makes). Unions are compared member by member.

IsEqual

export type IsEqual<A, B> =
  IsIdentical<A, B> extends true
    ? true
    : IsAny<A> extends true
      ? false
      : IsAny<B> extends true
        ? false
        : [Shape<A>] extends [Shape<B>]
          ? [Shape<B>] extends [Shape<A>]
            ? true
            : false
          : false;

The same type: identical, else the same in Shape (as Vitest's expectTypeOf tells them; tsd and tstyche only take identical ones).

CheckArgs

type CheckArgs<Result extends boolean, Positive extends boolean> = Result extends Positive ? [] : [never];

A check passes with no argument; one that fails asks for an argument, which makes tsc report it.

Expecting

type Expecting<Result extends boolean, Positive extends boolean, Actual, Expected> = Result extends Positive
  ? unknown
  : Mismatch<Actual, Expected>;

For a check given its type argument (<T>): one that fails, by its constraint, says what the types are.

EqualHint

type EqualHint<Actual, Expected, Positive extends boolean> = Positive extends true
  ? [Actual] extends [Expected]
    ? [Expected] extends [Actual]
      ? unknown
      : Mismatch<Actual, Expected>
    : Mismatch<Actual, Expected>
  : IsIdentical<Actual, Expected> extends true
    ? Mismatch<Actual, Expected>
    : unknown;

The constraint of toEqualTypeOf<T> (a cheap check: a deep one there would be circular), which says what the types are when it fails: they must be assignable both ways (to be equal), or, with not, not identical.
