ORM

@xufa/orm has models and QuerySets in the spirit of Django, on SQL and NoSQL databases, with no dependencies: SQLite, PostgreSQL, MongoDB, memory and files. The same models and queries run on every backend, and give the same results.

5databases (SQLite, PostgreSQL, MongoDB, memory, files) and 3 stores of objects (disk, memory, S3)
2×–18×Sequelize, where the ORM does the work (building queries, making objects)
0dependencies: its own drivers of PostgreSQL and MongoDB

Install

npm install @xufa/orm   # or: npm install xufa, and import from 'xufa/orm'

It needs Node.js 22.22.3 or later (24.15 or later on the 24 line); SQLite is node:sqlite.

A first model

import { Database, Model, fields, Count, Sum } from '@xufa/orm';

class Author extends Model {
  static fields = { name: fields.string({ maxLength: 100 }) };
}

class Book extends Model {
  static fields = {
    title: fields.string(),
    pages: fields.integer({ min: 1 }),
    author: fields.foreignKey(() => Author, { relatedName: 'books' }),
  };
}

const db = new Database({ backend: 'sqlite', filename: ':memory:' }); // or postgres, mongodb, memory, fs
db.register(Author, Book);
await db.connect();
await db.sync(); // creates the tables (migrations: see the Guide)

const ada = await Author.objects.create({ name: 'Ada' });
await Book.objects.bulkCreate([
  { title: 'Notes', pages: 120, author: ada },
  { title: 'Letters', pages: 80, author: ada },
]);

// Conditions across relations, the author loaded in the same query.
const long = await Book.objects.filter({ pages__gte: 100, author__name: 'Ada' }).selectRelated('author');
console.log(long.map((book) => `${book.title} by ${book.author.name}`));

// Aggregates by group.
console.log(await Author.objects.values('name').annotate({ books: Count('books'), pages: Sum('books__pages') }));

// Values checked by their fields before they are written.
try {
  await Book.objects.create({ title: 'Empty', pages: 0, author: ada });
} catch (err) {
  console.log(err.code, err.errors);
}
await db.close();
[ 'Notes by Ada' ]
[ { name: 'Ada', books: 2, pages: 200 } ]
XUFA_ORM_ERR_VALIDATION { pages: [ 'Ensure this value is at least 1.' ] }

Why @xufa/orm

  • One API on every database. Models, conditions (author__name__istartswith), aggregates, transactions and migrations are the same on SQLite, PostgreSQL and MongoDB, and give the same results: the test suite runs on each backend. A model can live in MongoDB while the others are in PostgreSQL.
  • Django's design, in JavaScript. Models with fields, a manager (objects), QuerySets that are lazy and chain, Q and F, migrations made by comparing the models with the schema (From Django).
  • Fast. Its own drivers (@xufa/pg, @xufa/mongo), queries compiled once for each shape: from 2 to 18 times Sequelize where the library does the work (Benchmarks).
  • What apps need, built in. Encrypted fields, TTL indexes, computed fields, tenants with a database each, caches shared between processes, an audit log, stores of files (S3, disk), and resources: the routes of a model in @xufa/http, validated and documented in OpenAPI.
