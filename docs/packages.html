Packages

Every part of xufa is a package of its own, with no dependencies, usable without the rest. Most have the API of a library you may know, and pass that library's test suite.

@xufa/pg

A PostgreSQL driver with the API of pg for what applications use: Client, Pool, query(text, values). The PostgreSQL backend of the ORM is made with it. 

const { Pool } = require('@xufa/pg');

const pool = new Pool({ connectionString: 'postgres://user:password@localhost:5432/app', max: 10 });
const { rows } = await pool.query('SELECT id, name FROM users WHERE name ILIKE $1', ['a%']);

const client = await pool.connect(); // a connection of its own, for a transaction
try {
  await client.query('BEGIN');
  await client.query('UPDATE accounts SET balance = balance - $1 WHERE id = $2', [100, 1]);
  await client.query('COMMIT');
} catch (err) {
  await client.query('ROLLBACK');
  throw err;
} finally {
  client.release();
}
  • Clients and pools: Client (connect, query, end, LISTEN/NOTIFY), Pool (query, connect, end, max, idleTimeoutMillis); connection strings, ssl, the PG* variables; SCRAM-SHA-256, MD5 and cleartext passwords.
  • COPY: copyRows(table, columns, rows) loads rows in COPY's binary format; copyFrom(sql, data) and copyTo(sql) stream COPY data in and out.
  • Cancelling: query({ text, values, signal }) with an AbortSignal, or a timeout, which also asks the server to stop the query.
  • Types: as pg, except that bigint is a number when it is a safe integer (a bigint otherwise; pg gives strings).
  • Speed: queries are prepared the second time their text runs, read and send binary values, and are pipelined: a pool sends queries to the least busy connection without waiting for the ones before.

@xufa/mongo

A MongoDB driver with the API of the official driver for what applications use most: BSON, the wire protocol, authentication, TLS, mongodb+srv://, a pool, sessions and transactions. The MongoDB backend of the ORM is made with it. 

const { MongoClient } = require('@xufa/mongo');

const client = await new MongoClient('mongodb://localhost:27017/app').connect();
const users = client.db().collection('users');

await users.insertOne({ name: 'Ada', born: new Date('1815-12-10') });
const found = await users.find({ name: /^a/i }, { sort: { name: 1 }, limit: 10 }).toArray();
for await (const group of users.aggregate([{ $group: { _id: '$era', n: { $sum: 1 } } }])) console.log(group);

const session = client.startSession();
await session.withTransaction(async () => {
  await users.insertOne({ name: 'Grace' }, { session });
});
await session.endSession();
  • Collections: find, findOne, aggregate, countDocuments, the inserts, updates, replaces and deletes, indexes; cursors with for await.
  • Deployments: replica sets (members found and checked, read preferences, failover), sharded clusters, retryable writes and reads, zstd and zlib compression.
  • BSON: ObjectId, Binary, Timestamp, Decimal128... int64 values are numbers when they are safe integers.
  • Speed: BSON encoded into a reused buffer, the commands of a tick written in one system call, many commands sharing a connection, and large unordered insertMany calls cut into parts that run in parallel.
  • Not yet: change streams.

@xufa/logger

A fast JSON logger with the API of pino. It is the logger of @xufa/http.

const pino = require('@xufa/logger');

const logger = pino({ level: 'debug', redact: ['req.headers.authorization'] });
logger.info('hello %s', 'world');
logger.child({ requestId: 'r1' }).warn({ user: 7 }, 'slow request');

const toFile = pino(pino.destination({ dest: './app.log', sync: false, mkdir: true }));

pino's options, methods and output: levels, child(), formatters, serializers, redact, mixin, hooks, multistream() and destination(). Not supported: transports. Give it a stream, or pipe the output of the process (node app.js | pino-pretty).

@xufa/router

A fast HTTP router with the API of find-my-way.

const http = require('node:http');
const router = require('@xufa/router')({ ignoreTrailingSlash: true });

router.get('/users/:id', (req, res, params) => res.end(`user ${params.id}`));
router.on(['GET', 'HEAD'], '/files/*', (req, res, params) => res.end(params['*']));

http.createServer((req, res) => router.lookup(req, res)).listen(3000);

Parametric, multi-parametric, regexp and wildcard routes, constraints, and every option of find-my-way. It adds match(method, url), which finds the route without calling it and leaves the query string unparsed, and finds static paths with one map lookup.

@xufa/serializer

JSON serializers compiled from JSON Schema, with the output of fast-json-stringify. 

const build = require('@xufa/serializer');

const stringify = build({
  type: 'object',
  properties: { id: { type: 'integer' }, name: { type: 'string' }, tags: { type: 'array', items: { type: 'string' } } },
});

stringify({ id: 1, name: 'Ada', tags: ['a'], password: 'x' }); // '{"id":1,"name":"Ada","tags":["a"]}'

Only the properties of the schema are written, so nothing leaks. A serializer can write a string, or UTF-8 bytes (output: 'bytes', and toBuffer()), which saves copying large responses; output: 'auto', the default, picks bytes when the size is unknown (arrays, maps, recursion).

@xufa/inject

Fake HTTP requests to a request handler, without a socket, with the API of light-my-request. It is inject() of @xufa/http, and works with any (req, res) handler. 

const inject = require('@xufa/inject');

const res = await inject(handler, { method: 'POST', url: '/items?x=1', payload: { a: 1 } });
res.statusCode; // 200
res.json();

@xufa/boot

Loading of plugins, asynchronously and in order, with encapsulation, after, ready and close hooks and timeouts, with the API of avvio. 

const boot = require('@xufa/boot');

const app = boot({ name: 'app' });
app.use(async (instance, options) => {
  instance.db = await connect(options.url);
}, { url: 'postgres://...' });
app.onClose((instance, done) => instance.db.end(done));
await app.ready();

@xufa/errors

Classes of errors with a code, a status code and a formatted message, with the API of @fastify/error. 

const createError = require('@xufa/errors');

const NotFound = createError('APP_NOT_FOUND', 'User %s not found', 404);
const err = new NotFound('ada');
err.code; // 'APP_NOT_FOUND'
err.statusCode; // 404
err.message; // 'User ada not found'

@xufa/cluster

Runs an app in a cluster of processes: the primary forks the workers (one per CPU by default), forks again those that die (waiting longer each time one dies soon after it started), and stops them all gracefully on stop(), SIGINT or SIGTERM: every worker runs its shutdown functions, and those that do not exit in shutdownTimeout are killed. 

const { start, bus } = require('@xufa/cluster');

start({
  workers: 4, // os.availableParallelism() by default; 0 runs everything in one process
  primary: async ({ bus }) => {
    const counts = new Map();
    bus.on('hit', (path) => counts.set(path, (counts.get(path) || 0) + 1));
    bus.on('hits', () => Object.fromEntries(counts)); // a request: its result is the reply
  },
  worker: async ({ id, onShutdown }) => {
    const app = makeApp();
    app.addHook('onRequest', async (request) => bus.send('hit', request.routeOptions.url));
    app.get('/hits', () => bus.request('hits'));
    await app.listen({ port: 3000 });
    onShutdown(() => app.close());
  },
});
BusFromTo
bus.on(event, handler), bus.off(event, handler)Handlers get (data, sender); their result is the reply of requests
bus.send(event, data)A workerThe primary
bus.request(event, data, { timeout })A workerThe primary, and back: a promise of the reply
bus.sendTo(workerId, event, data)The primaryOne worker
bus.broadcast(event, data, { others })AnyoneEvery worker (others leaves the sender out)

Messages use the structured clone of Node.js: Dates, Maps, Sets, BigInts and typed arrays arrive as they were sent. In one process (no workers), the same calls reach the handlers of that process, so code written for a cluster runs as it is in development and in tests. The ORM's SharedCache and LocalCache use this bus (see Caches).
