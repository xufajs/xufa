Overview Reference

@xufa/boot

Loading of plugins, asynchronously and in order, with encapsulation, after, ready and close hooks and timeouts. It has the API of avvio, passes its test suite, has no dependencies, and loads the plugins of @xufa/http (app.register()). It works on its own, for any object that is set up in steps.

Quick start

npm install @xufa/boot
import boot from '@xufa/boot';

const server = { name: 'app' };
const app = boot(server); // server gets use(), after(), ready(), close() and onClose() too

app.use(async (instance, options) => {
  instance.db = await connect(options.url); // instance is server (or what override() gives)
}, { url: 'postgres://...' });

app.after((err) => {
  if (err) throw err;
  // every plugin registered before after() is loaded: server.db is set
});

app.onClose((instance, done) => instance.db.end(done));

await app.ready();
await app.close();

Plugins

A plugin is a function of the instance and its options:

async function plugin(instance, options) { /* await what it needs */ }
function callbackPlugin(instance, options, done) { setUp(instance, options); done(); }

app.use(plugin, { level: 1 });
app.use(plugin, (instance) => ({ url: instance.config.url })); // options from the instance, when it loads
app.use(import('./plugin.mjs')); // a promise of a module: its default export

A plugin can register plugins of its own; they load before the plugins registered after it. A plugin that throws, or calls done(err), stops the boot: the error reaches the next after() or ready().

Order and after()

app.use(database);
app.use(cache);
app.after(async () => {
  // database and cache are loaded
});
app.use(routes); // loads after the after() above

Plugins load one after the other, in the order they were registered. after(fn) runs when every plugin registered before it is loaded; it takes (err), (err, done), (err, instance, done), or is an async function; called without a function, it gives a promise.

ready()

await app.ready() (or ready(fn)) when every plugin is loaded; the error of the boot rejects it. With autostart (the default), loading starts on the next tick after the first use(); start() starts it at once.

close() and onClose()

app.onClose(async (instance) => instance.db.end()); // or (instance, done)
await app.close(); // the onClose functions, in reverse order of registration

await using app = boot(server) closes it at the end of its block (Symbol.asyncDispose).

Encapsulation

app.override = (parent, plugin, options) => {
  const child = Object.create(parent); // what the plugin decorates stays in it
  child.prefix = (parent.prefix || '') + (options.prefix || '');
  return child;
};

override(instance, plugin, options) gives the instance a plugin gets: return a new object for a scope of its own, or the same one to share it. By default every plugin gets the same instance. xufa's override gives each plugin a scope of its own, unless the plugin has plugin[Symbol.for('skip-override')] = true (what fastify-plugin sets).

Options

OptionDefaultWhat it does
exposeOther names for the methods put on the server: { use: 'register', after, ready, close, onClose }.
autostarttrueLoading starts by itself; false: at start() or ready().
timeout0Milliseconds a plugin has to load (0: no limit); past it, BOOT_ERR_PLUGIN_EXEC_TIMEOUT.

boot(server, options, done): done is called when it is ready.

Events

start (every plugin is loaded), preReady (before the ready functions run) and close.

The tree of plugins

console.log(app.prettyPrint()); // the plugins, nested, with the milliseconds each one took to load
app.toJSON(); // the same, as an object

Errors

boot.errors, made with @xufa/errors: BOOT_ERR_PLUGIN_NOT_VALID, BOOT_ERR_PLUGIN_EXEC_TIMEOUT, BOOT_ERR_READY_TIMEOUT, BOOT_ERR_CALLBACK_NOT_FN, BOOT_ERR_ROOT_PLG_BOOTED, BOOT_ERR_PARENT_PLG_LOADED, BOOT_ERR_EXPOSE_ALREADY_DEFINED and BOOT_ERR_ATTRIBUTE_ALREADY_DEFINED.

Coming from avvio

  • The API and the behaviour are avvio's (its test suite passes).
  • The error codes are BOOT_ERR_* where avvio has AVV_ERR_*.
  • The queue of plugins is part of the package (avvio uses fastq), with the same semantics.

avvio's declarations, with errors, kBoot and kPluginMeta.
