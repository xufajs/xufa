Overview Reference

@xufa/html

HTML parsed as browsers parse it, and a DOM to read and change what was parsed, with no dependencies. The parser is parse5's, ported with its tests; @xufa/html/dom is a DOM of the DOM standard on it, for code made for browsers that reads trees: a sanitizer (@xufa/purify runs DOMPurify on it), a scraper, a test.

Quick start

npm install @xufa/html
import { createWindow } from '@xufa/html/dom';

const { document } = createWindow('<ul id="list"><li class="a">One<li>Two</ul><p>a<b>b<i>c</p>d');
console.log(document.querySelectorAll('#list > li').length, document.querySelector('li.a').textContent);
console.log(document.body.innerHTML);

The parser

parse(html, options) gives a document and parseFragment(html) (or parseFragment(context, html)) a fragment, as parse5 has them: a tree of plain objects, or of your own with a treeAdapter. serialize(node) and serializeOuter(node) write them as the HTML standard says. It is the HTML standard's tokenizer and tree construction: implied and misnested tags, tables and what goes before them, templates, SVG and MathML with their names and attributes, character references. scriptingEnabled, sourceCodeLocationInfo, onParseError and the Tokenizer are parse5's. 

const fragment = parseFragment('<table>x<td>y<svg viewbox="0 0 1 1"><foreignobject><p>&notin;');
console.log(serialize(fragment));
console.log(parse('<title>T</title>').childNodes[0].childNodes.map((node) => node.nodeName));

The DOM

createWindow(html) gives a window with its document and the interfaces of browsers (Node, Element, DOMParser, NodeFilter, ...), as libraries made for browsers take them. Documents are parsed with scripting disabled, as DOMParser does in browsers. Elements of HTML (of their interfaces: HTMLDivElement, HTMLHeadingElement... and HTMLUnknownElement), SVG and MathML, attributes (names checked as the DOM standard has them now, lower-cased on HTML elements, namespaces), text, comments, CDATA, processing instructions, doctypes and fragments; innerHTML and outerHTML both ways (templates in their content), cloneNode, importNode, adoptNode, querySelector and matches (types, ids, classes, attributes, :not(), first, last and only child, :empty, :root, :scope, :nth-child() and :nth-last-child() (with of S), :nth-of-type(), :nth-last-of-type(), the first, last and only of a type, :is(), :where(), :has(), the namespace prefixes *| and |, the combinators, CSS escapes), classList and relList, dataset, the namespace lookups, isEqualNode, compareDocumentPosition, and href and src of links and images.

The NodeIterator is live: when nodes are removed, its reference moves as the standard says, so a tree can be changed while it is walked, as a sanitizer does. Documents and forms have the names of the properties browsers give them (cookie, location, submit, ...), so a sanitizer that protects against DOM clobbering finds them. There are no events, layout, styles, scripts, timers or networking. 

const { document } = createWindow('<div><b>1<i>2</i></b><u>3</u></div>');
const iterator = document.createNodeIterator(document.body, NodeFilter.SHOW_ELEMENT);
const seen = [];
for (let node = iterator.nextNode(); node; node = iterator.nextNode()) {
  seen.push(node.nodeName);
  // An element replaced by its children while it is walked: the walk goes through them.
  if (node.nodeName === 'B') node.replaceWith(...node.childNodes);
}
console.log(seen.join(' '), document.body.innerHTML);
BODY DIV B I U <div>1<i>2</i><u>3</u></div>

XML

DOMParser parses XML too (application/xml, text/xml, application/xhtml+xml, image/svg+xml): namespaces, the five entities and character references, CDATA sections, comments and processing instructions; a document that is not well formed is a <parsererror> document, as in browsers. Elements of XML documents are serialized as the DOM Parsing standard says (namespaces declared where needed, <br /> for void elements of XHTML), and their innerHTML parses XML or throws a SyntaxError.

How it was checked

  • parse5's tests, ported by tools/port-parse5: 10,596 pass (html5lib's tree construction and tokenizer suites, its fork with codes of parse errors, serialization, source locations).
  • Its own tests: the live iterator, attributes and namespaces, innerHTML, templates, importing, XML, selectors, classList, the names of document and forms.
  • The DOM standard's tests in web-platform-tests (nodes, traversal, collections, token lists: 410 pages, copied by tools/port-wpt), run as a browser runs them with WPT's own testharness.js: 9,734 subtests pass. The others are listed with their reasons in test/wpt-expected.json: what this DOM does not have (frames, events, MutationObserver, Range, shadow DOM, moveBefore(), the selectors of states of forms and user input...), and 11 bugs still to fix.
  • DOMPurify's tests on it (in @xufa/purify), and the same output as DOMPurify on jsdom for its XSS vectors and 37,000 random markups; where jsdom differs from Chrome (text inside a table), it is as Chrome.
