Overview Reference

@xufa/forms

Forms as Django's: fields that take what a body gives (texts, dates, choices, objects of a model, files of xufa.formBody), clean it and say what is wrong with it, forms with their errors by field and their HTML, and forms of models of the ORM whose fields come from the model and are checked by it (its validation, rules, unique values and constraints). No dependencies.

Quick start

import { Form, fields, ValidationError } from '@xufa/forms';

class RenewBookForm extends Form {
  static fields = {
    renewalDate: fields.date({ help: 'Enter a date between now and 4 weeks (default 3).' }),
  };

  cleanRenewalDate(value) {
    if (value < '2026-01-01') throw new ValidationError('Invalid date - renewal in past');
    return value;
  }
}

const form = new RenewBookForm({ data: { renewalDate: '2025-12-24' } }); // request.body
console.log(await form.isValid(), form.errors);
const good = new RenewBookForm({ data: { renewalDate: '2026-11-02' } });
console.log(await good.isValid(), good.cleanedData);
console.log(new RenewBookForm().asP());

true { renewalDate: '2026-11-02' }

Every field takes required (true), label (made of its name: dateOfBirth is "Date of birth"), help (HTML, as Django's help_text), initial, disabled (shown, its value the initial one), validators (functions that give a message or throw a ValidationError) and attrs of its input. A form gets the fields of its parents; null takes one out. messages gives a field its own texts by the code of the error (Django's error_messages): { required, invalid, min, max... }.

The limits of a date are days, 'today', days relative to today ('+4w', '-1d', '+3m', '+1y') or a function, read when the form is checked (and written in its input, for the browser's picker). Django's renewal form needs no clean method: 

class RenewBookForm extends Form {
  static fields = {
    renewalDate: fields.date({
      min: 'today',
      max: '+4w',
      messages: { min: 'Invalid date - renewal in past', max: 'Invalid date - renewal more than 4 weeks ahead' },
    }),
  };
}

new RenewBookForm({ initial: { renewalDate: addDays(21) } }); // three weeks ahead at first

today(), addDays(days, from), addMonths(months, from) and dateOf(spec) give days as 'YYYY-MM-DD' texts, as date fields hold them, in the time of the machine (Django's date.today()).

Cleaning

await form.isValid() cleans each field (its value, then required, its checks and its validators), then the method clean<Name>(value) of the form (it gives the value, may be async), then clean(data) for the checks of several fields. form.errors are the messages by field, and those of the whole form under __all__ (nonFieldErrors()); addError(name, message) adds one. cleanedData holds the values. A form without data (not sent) is not valid and has no errors; prefix names its inputs prefix-name (several forms in a page). 

import { Form, fields, ValidationError } from '@xufa/forms';

class ContactForm extends Form {
  static fields = {
    email: fields.email(),
    kind: fields.choice({ choices: [['q', 'Question'], ['c', 'Complaint']] }),
    order: fields.integer({ required: false, min: 1 }),
  };

  clean(data) {
    if (data.kind === 'c' && !data.order) throw new ValidationError('A complaint names its order');
    return data;
  }
}
const form = new ContactForm({ data: { email: 'ada@', kind: 'c' } });
await form.isValid();
console.log(form.errors);
{
  email: [ 'Enter a valid email address.' ],
  __all__: [ 'A complaint names its order' ]
}

HTML

asTable(), asP(), asUl() and asDiv() write the form: labels, inputs with the values sent (or initial), errors as <ul class="errorlist">, help texts. In a template of @xufa/template, with the token of the session: 

<form method="post">
  <input type="hidden" name="_csrf" value="{{ csrfToken }}">
  <table>{{{ form.asTable() }}}</table>
  <input type="submit" value="Submit">
</form>

{{#each form.visibleFields as field}}
  <div class="field">{{{ field.labelTag() }}} {{{ field.widget({ class: 'input' }) }}} {{{ field.errorsHtml() }}}</div>
{{/each}}

A field of a form (form.field(name), form.boundFields) has label, help, errors, value, id and htmlName, and writes labelTag(), widget(attrs), errorsHtml() and helpHtml(). Values are escaped; inputs have required, maxlength, min and the like for the browser, and aria-invalid with errors.

ModelForm

A form of a model: its fields are made of those of the model (meta.fields, or '__all__'; meta.exclude), with their labels and help, choices with labels as selects (without the empty option when they have a default), foreign keys and many-to-many as choices of their objects, and required unless the field may be blank. meta.labels, meta.help and meta.widgets change them; fields of the form (static fields) go over them. 

import { ModelForm } from '@xufa/forms';

class BookForm extends ModelForm {
  static meta = { model: Book, fields: ['title', 'author', 'isbn', 'genre', 'status'] };
}

const form = new BookForm({
  data: { title: 'Notes', author: String(ada.pk), isbn: '9780000000001', genre: [String(poetry.pk)], status: 'a' },
});
console.log(await form.isValid());
const book = await form.save();
console.log(book.title, book.authorId, (await book.genre.all()).map(String));

const again = new BookForm({ data: { title: 'Copy', isbn: '9780000000001', genre: [String(poetry.pk)] } });
console.log(await again.isValid(), again.errors);
true
Notes 1 [ 'Poetry' ]
false {
  status: [ 'This field is required.' ],
  isbn: [ 'Book with this ISBN already exists.' ]
}

After the form cleans its fields, the model checks the object made of them (its validation and rules: their messages go under their fields, or to the form; the fields of the model left out of the form are not checked, the view fills them with save({ commit: false })), then its unique fields and unique constraints (of the fields without errors) are asked to the database, as Django's validate_unique: a constraint's message (Lower('name')...) goes under its field.

modelFormOf(Book, { fields: ['title', 'isbn'] }) makes the class of a form, as Django's modelform_factory (generic views of a list of fields).

Saving

new BookForm({ data, instance }) changes an object: its values (and those of its many-to-many) are those shown, and its own values are not duplicates of itself. await form.save() saves the object and then its many-to-many; save({ commit: false }) gives it unsaved (then saveLinks(object)). Saving a form that is not valid throws. A unique value saved by another at the same time is a ValidationError, with its message under its field.

In a route

app.register(xufa.formBody); // request.body of HTML forms
app.route({
  method: ['GET', 'POST'],
  url: '/catalog/book/:pk/update/',
  name: 'book-update',
  preHandler: app.accounts.permissionRequired('Book.change'),
  handler: async (request, reply) => {
    const book = await Book.objects.get({ pk: request.params.pk });
    const form = new BookForm({ instance: book, data: request.method === 'POST' ? request.body : null });
    if (await form.isValid()) {
      await form.save();
      return reply.redirect(app.reverse('book-detail', [book.pk]));
    }
    await form.prepare(); // the objects of its choices
    return reply.view('catalog/form', { form });
  },
});

Languages

Its messages are keys with English defaults (FORMS_MESSAGES); @xufa/i18n gives them in the language of each request: i18n.translateForms(forms) (es, fr, de, pt, it, and the catalogs of the app over them, as forms.required).
