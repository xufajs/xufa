@xufa/serializer

JSON serializers compiled from JSON Schema, with the output of fast-json-stringify, and no dependencies. A serializer writes only the properties of its schema, each as its type, and writes large values as UTF-8 bytes instead of a string, which saves the copy V8 makes before a string goes to a socket. It writes the responses of @xufa/http and passes fast-json-stringify's test suite.

Quick start

npm install @xufa/serializer
import build from '@xufa/serializer';

const stringify = build({
  type: 'object',
  properties: {
    id: { type: 'integer' },
    name: { type: 'string' },
    tags: { type: 'array', items: { type: 'string' } },
    created: { type: 'string', format: 'date-time' },
  },
  required: ['id'],
});

stringify({ id: 1, name: 'Ada', tags: ['a'], password: 'x', created: new Date(0) });
// '{"id":1,"name":"Ada","tags":["a"],"created":"1970-01-01T00:00:00.000Z"}'

Why a schema

  • No data leaks: only the properties of the schema are written; a password added to a model by mistake does not reach the response.
  • Speed: the code is compiled for the shape, so nothing is discovered at run time.
  • Types: each value is written as its type: "7" for an integer is written 7, a Date for a string its ISO text.

Schemas

The JSON Schema of fast-json-stringify: type (one or a list, null included), properties, required (a missing required property is an error), additionalProperties, patternProperties, items (one schema, or a list for tuples), default, const, enum, nullable, allOf, anyOf, oneOf, if/then/else, $ref and $defs/definitions, and the formats date-time, date, time and unsafe (strings written without escaping, when you know they need none). 

build({
  type: 'object',
  properties: {
    kind: { enum: ['user', 'team'] },
    owner: { anyOf: [{ type: 'string' }, { type: 'object', properties: { id: { type: 'integer' } } }] },
  },
  additionalProperties: { type: 'number' }, // the other properties, as numbers
});

The branches of anyOf, oneOf and if are chosen by predicates compiled from their schemas, not by a validator.

Strings and bytes

A serializer joins the JSON with + (a string), or writes it as UTF-8 bytes to a buffer it shares with the other serializers. Joined strings are a tree of pieces that V8 copies into one string before it can be written to a socket; for large values that copy costs about as much as making the JSON. Bytes have no such copy, but reading them back costs more than a small string. So output: 'auto' (the default) writes bytes when the size is unknown (arrays, maps, recursion) and strings otherwise; 'string' or 'bytes' choose. 

const list = build({ type: 'array', items: { type: 'object', properties: { id: { type: 'integer' } } } });
list([{ id: 1 }]); // '[{"id":1}]'
list.toBuffer([{ id: 1 }]); // <Buffer 5b 7b 22 69 64 22 3a 31 7d 5d>: the bytes, in a Buffer of their own

Serializers that write bytes have toBuffer(value); xufa sends that Buffer as it is, which is why its large JSON responses are 1.4 to 1.7 times as fast as fastify's.

References and shared schemas

const address = { $id: 'address', type: 'object', properties: { city: { type: 'string' } } };
const stringify = build(
  {
    type: 'object',
    properties: { home: { $ref: 'address' }, work: { $ref: 'address#' }, parts: { $ref: '#/$defs/parts' } },
    $defs: { parts: { type: 'array', items: { type: 'string' } } },
  },
  { schema: { address } }
);

In xufa

The response schemas of routes, by status code, compile to serializers; the shared schemas of app.addSchema() are their external schemas. Responses without a schema use JSON.stringify. 

app.get('/users/:id', {
  schema: { response: { 200: { type: 'object', properties: { id: { type: 'integer' }, name: { type: 'string' } } } } },
}, async (request) => db.users.find(request.params.id)); // only id and name are sent

Coming from fast-json-stringify

  • The schemas, the options and the output are fast-json-stringify's (its test suite passes).
  • Added: output and toBuffer().
  • Not there: mode: 'standalone' and restore(), and an ajv instance (options.ajv only gives coerceTypes).
