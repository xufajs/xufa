Overview Reference

@xufa/discovery

The nodes of a service find each other on the network by UDP: each one says it is there every second, with its meta (its URL, its role...), and the others hold it as a peer until it says goodbye or is not heard for a while. Multicast on a local network, broadcast where multicast is filtered, and seeds where there is neither. With a secret, packets are encrypted and authenticated. No dependencies.

Quick start

npm install @xufa/discovery
const { Discovery } = require('@xufa/discovery');

const discovery = new Discovery({
  service: 'shop-api',
  meta: { url: `http://${process.env.HOST}:3000`, role: 'api' },
  secret: process.env.DISCOVERY_SECRET, // 16 bytes or more
});
discovery.on('up', (peer) => console.log('up', peer.meta.url));
discovery.on('down', (peer, reason) => console.log('down', peer.id, reason)); // 'bye' or 'timeout'
await discovery.start();

discovery.peers; // [{ id, service, address, port, meta, since, lastSeen }]
await discovery.waitFor((peers) => peers.length >= 2); // three nodes, this one included

How it works

  • A node that starts says hello; the nodes that hear it answer at once, so it sees them without waiting for an interval.
  • Every interval (1 second, ±10% so that nodes do not all send at once) each node says it is there, with its meta. A change of meta (setMeta()) is said at once.
  • A node that stops says goodbye (down, 'bye'); one that dies is forgotten after timeout (3.5 intervals: down, 'timeout').
  • Packets carry the service: nodes of other services on the same port are not peers. Every packet fits in one Ethernet frame (1400 bytes), so none is split.

Transports

  • Multicast, the default: the nodes join a group on every IPv4 interface, so nodes of one machine and of the local network find each other. Routers do not pass it on unless ttl is raised and they route multicast.
  • Broadcast: the whole subnet, where switches filter multicast. It does not cross routers.
  • Unicast: the node says it is there to its seeds and to every peer it knows, and passes on the addresses it knows, so a node that knows one seed finds every node that seed knows. Each node binds a port of its own.

In clouds

AWS, Google Cloud and Azure carry neither multicast nor broadcast, nor do most networks of containers on several hosts: there, use transport: 'unicast' with one or two seeds that are always there (a fixed address, or a name that DNS gives, as the service of Kubernetes or Docker Compose), and open the UDP port between the nodes. 

new Discovery({ transport: 'unicast', port: 29050, seeds: ['discovery.internal:29050'], secret, meta });

Security

Without a secret, any machine of the network can be a peer, read the meta and forge packets: the meta is no place for secrets, and a peer is not trusted. With a secret, packets are sealed with AES-256-GCM (a key derived from the secret and the service by HKDF), so they cannot be read or changed by those without it, and packets older than maxSkew or seen already (a sequence per node) are refused. Hellos are answered at most once every 20 ms, so forged ones do not make a node flood the network.

With @xufa/cluster

One discovery by machine, in the primary; the workers ask it through the bus:

const { start, bus } = require('@xufa/cluster');
const { Discovery } = require('@xufa/discovery');

start({
  primary: async ({ onShutdown }) => {
    const discovery = await new Discovery({ service: 'shop-api', meta: { url: myUrl } }).start();
    bus.on('peers', () => discovery.peers.map((peer) => peer.meta.url));
    onShutdown(() => discovery.stop());
  },
  worker: async () => {
    const urls = await bus.request('peers');
  },
});
