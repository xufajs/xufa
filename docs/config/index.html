Overview Reference

@xufa/config

The configuration of an app, from layers: defaults, files of JSON, YAML or JS by environment, local files, .env files, variables of the environment and overrides. Templates in its values are safe expressions; a schema converts, fills in defaults and checks, every error at once; secrets are redacted when it is shown; and it is frozen, with get('a.b') failing for keys that are not there.

Quick start

npm install @xufa/config
const { loadConfig } = require('@xufa/config'); // or require('xufa/config')

// With PORT=8080 and DATABASE_URL=postgres://app:secret@db/app in the environment:
const config = loadConfig({
  envPrefix: 'APP',
  schema: {
    server: { port: { type: 'port', default: 3000, env: 'PORT' } },
    db: { url: { type: 'url', required: true, env: 'DATABASE_URL', sensitive: true } },
  },
});
console.log(config.server.port, typeof config.server.port); // the PORT of the environment, as a number
console.log(config.redacted()); // what is safe to log

// Without DATABASE_URL:
try {
  loadConfig({ schema: { db: { url: { type: 'url', required: true, env: 'DATABASE_URL' } } }, environment: {} });
} catch (err) {
  console.log(err.message);
}
8080 number
{ server: { port: 8080 }, db: { url: '[redacted]' } }
The configuration (development) has errors:
  - db.url: is required (set DATABASE_URL)

Layers

Each layer is merged over the one before (objects key by key; arrays and other values replace):

  1. defaults, an object of the options;
  2. config/default.json (or .yaml, .yml, .js, .cjs);
  3. config/{env}.*: the env option, or NODE_ENV, or development;
  4. config/local.*, then config/local-{env}.*: of the machine, kept out of git;
  5. the remote sources, in their order (with loadRemoteConfig());
  6. the variables of the schema (env: 'PORT');
  7. the variables with the prefix: with envPrefix: 'APP', APP__DB__POOL__MAX=20 sets db.pool.max (keys found whatever their case; without a schema, a value takes the type of the one it replaces);
  8. overrides, an object of the options.

.env files

The variables are those of the process, with what .env, .env.{env}, .env.local and .env.{env}.local have that they do not (the later first). dotenv: false reads none, dotenv: ['secrets.env'] those; populate: true sets in process.env what it does not have. Values in double quotes have escapes and can be several lines; parseDotenv(text) reads one.

Templates

server:
  port: '{{ Number(env.PORT ?? 3000) }}'
  url: 'http://{{ config.server.host }}:{{ config.server.port }}'

A text with {{ expression }} is resolved after the layers are merged, with env and config (the other keys, resolved first). A text that is only a template is the value of its expression; in a text with more, each is written in it. A template that is undefined, alone, leaves its key missing (its default). The expressions are those of @xufa/expression: they cannot assign nor reach the process, and a name that is not env, config nor a global (a typo) is an error. Cycles are errors.

Remote sources

loadRemoteConfig(options) takes the options of loadConfig() and remote: sources read at once (it is async) and merged in their order, after the files and before the variables of the environment (a variable still overrides what a server says). 

const { loadRemoteConfig, sources } = require('@xufa/config');

const config = await loadRemoteConfig({
  schema,
  remote: [
    sources.http({ url: 'https://config.internal/apps/shop.yaml' }),
    sources.consul({ prefix: 'apps/shop' }), // apps/shop/db/host is db.host
    sources.vault({ path: 'shop/production', at: 'credentials' }), // KV 2 of Vault
    sources.ssm({ path: '/shop/production' }), // Parameter Store of AWS
    sources.secretsManager({ secretId: 'shop/api', at: 'api' }), // AWS Secrets Manager
    sources.directory({ dir: '/run/secrets', at: 'files', sensitive: true }), // Docker, Kubernetes
  ],
  cacheFile: '.config-cache.json',
});
SourceWhat it reads
http({ url, headers, format })A document of JSON or YAML; with an ETag, one not changed is not sent again.
consul({ prefix | key })The keys under a prefix as a tree, or one key as a document. CONSUL_HTTP_ADDR, CONSUL_HTTP_TOKEN.
vault({ path, mount, kv, token | roleId + secretId })A secret of the KV engine (2 or 1) of Vault or OpenBao, with a token or AppRole. VAULT_ADDR, VAULT_TOKEN... Sensitive, without templates.
ssm({ path, region, credentials, endpoint })The parameters of the Parameter Store of AWS under a path, as a tree, SecureStrings decrypted. AWS_REGION, AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_SESSION_TOKEN; calls signed with Signature Version 4, without an SDK. Sensitive, without templates.
secretsManager({ secretId, versionStage, region, credentials, endpoint })A secret of AWS Secrets Manager: its JSON as keys, or its text under value. Sensitive, without templates.
directory({ dir })A key for each file; .json and .yaml files are their documents; hidden ones left out. Without templates.
{ name, load({ env, name, signal }) }One of your own.
  • Options of every source: at (the key it is put under), optional, sensitive (redacted, never cached), templates: false (a password with {{ is that text), timeout (5 s an attempt), retries (2).
  • A source that fails takes its last tree from cacheFile (not sensitive ones), so the app starts while its config server is down; or is left out when optional. The rest fail together, in one ConfigError.

Watching

const watcher = await watchConfig(options, {
  interval: '30s',
  onChange: (config, previous, changed) => log.info({ changed }, 'the configuration changed'),
  onError: (err) => log.warn(err), // the configuration there was is kept
});
watcher.current.flags.beta;

Every layer is read again every interval; when something changed, watcher.current is a new (frozen) configuration and onChange gets it, the one before and the paths that changed. A reading that fails keeps the one there was. refresh() reads it now; stop() stops it.

The keys of Consul are followed with blocking queries, which Consul answers when they change: a change is read at once, not at the next interval (blocking: false leaves only the interval). Their connection does not keep the process alive, and a failure is tried again (1 s, then twice as long, 30 s at most).

The schema

The keys, nested as the configuration; a key whose type is a text is one value: string, number, integer, boolean (true, yes, on, 1...), port, url, duration ('1h30m' is milliseconds), array (JSON or commas, with items), object (JSON) and any. Options: default, required, nullable, env, values, pattern, min, max, sensitive, doc; strict: true makes keys out of the schema errors. 

The configuration (production) has errors:
  - db.url: is required (set DATABASE_URL)
  - server.port: 70000 is not a port (0-65535)

Every error is in one ConfigError, each with its path. In TypeScript, the type of the configuration follows from its schema, or is the one given (loadConfig<AppConfig>()).

The configuration

  • Frozen, deep; its keys are its own, its methods are not among them.
  • get(path): the value at 'a.b'; a key that is not there is an error. has(path).
  • redacted(): a copy without the keys sensitive in the schema and those named as secrets (password, secret, token, apiKey...); JSON.stringify and console.log show it.
  • sources: the files read, and the remote sources.
