HTTP

@xufa/http is the HTTP layer of xufa: a fast web framework for Node.js with the API of fastify: routes, hooks, plugins, decorators, schemas that validate requests and serialize replies. It has no dependencies outside the packages of xufa, and the package xufa gives it too. Try an app of it in your browser, in the playground.

Install

npm install @xufa/http   # or: npm install xufa

It needs Node.js 22.22.3 or later (24.15 or later on the 24 line). CommonJS and ES modules both work:

const xufa = require('@xufa/http');
// import xufa from '@xufa/http'
// import { xufa } from '@xufa/http'

A first app

const xufa = require('@xufa/http');

const app = xufa({ logger: true });

const books = new Map([[1, { id: 1, title: 'Dune', pages: 412 }]]);

const Book = {
  type: 'object',
  properties: { id: { type: 'integer' }, title: { type: 'string' }, pages: { type: 'integer' } },
};

// GET /books/1: the id converted to a number, the reply written by a serializer compiled from Book.
app.get(
  '/books/:id',
  { schema: { params: { type: 'object', properties: { id: { type: 'integer' } } }, response: { 200: Book } } },
  async (request, reply) => books.get(request.params.id) ?? reply.code(404).send({ message: 'No such book' })
);

// POST /books: the body validated (400 with the reason when it is not valid).
app.post(
  '/books',
  {
    schema: {
      body: {
        type: 'object',
        required: ['title'],
        properties: { title: { type: 'string', minLength: 1 }, pages: { type: 'integer', minimum: 1 } },
        additionalProperties: false,
      },
      response: { 201: Book },
    },
  },
  async (request, reply) => {
    const book = { id: books.size + 1, ...request.body };
    books.set(book.id, book);
    reply.code(201);
    return book;
  }
);

await app.listen({ port: 3000 });

Why @xufa/http

  • fastify's API, and its tests. Code written for fastify runs on it, and so do plugins written with fastify-plugin. fastify's own test suite runs against it (main branch, 6.0.0-alpha.4, ported), and its TypeScript declarations are fastify's, with their type tests.
  • Faster. It writes the head of most responses itself, compiles its router, leaves the query string unparsed until it is read, and writes large JSON replies as bytes: from 1.06× to 1.96× the requests of fastify in the process, 1.02× to 1.66× over the loopback (Benchmarks).
  • One set of packages. What fastify takes from a dozen packages (a logger, a router, ajv, a serializer...), xufa has in its own, written together and tested together, with no dependencies to audit.
  • The rest of the framework around it. An ORM, authentication, OpenAPI, WebSockets, configuration, a cluster, a scheduler: each one a plugin of the app (below).

The API is fastify's

Everything in fastify's documentation applies: server options, routes, hooks, plugins and encapsulation, decorators, validation and serialization, content type parsers, reply, request, the logger, inject() and the type providers of TypeScript. The API page lists all of it as xufa has it. What is different (the names of errors, the validator, the logger, a few options) is in From fastify: for most apps, moving is changing require('fastify') into require('@xufa/http').

Its parts

What fastify takes from other packages, xufa has in its own, each usable alone:

fastify usesxufa usesFor
pino@xufa/loggerThe logs of the app and of each request
find-my-way@xufa/routerFinding the route of a request
ajv@xufa/schemaValidating requests (and replies, when asked)
fast-json-stringify@xufa/serializerWriting replies with a response schema
light-my-request@xufa/injectapp.inject(): requests without a socket, for tests
avvio@xufa/bootLoading plugins in order
@fastify/error@xufa/errorsErrors with a code and a status
fastify-pluginxufa.pluginPlugins that share what they add
