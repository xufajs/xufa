Overview Reference

@xufa/netcache

A cache shared by the machines of a service. Each node keeps a copy, so reads do not leave the machine, and every set, delete and clear is sent to the other nodes over TCP; the nodes find each other with @xufa/discovery. It has the methods of the caches of @xufa/orm, so the models of a database, the lockouts of @xufa/auth or anything else can be cached once for every machine.

Quick start

npm install @xufa/netcache
const { NetCache } = require('@xufa/netcache');

const cache = await new NetCache({ secret: process.env.CACHE_SECRET, service: 'shop' }).start();

await cache.set('rates', { eur: 1.08 }, 60000); // every machine, for a minute
await cache.get('rates'); // a copy, from this machine
await cache.delete('rates'); // gone from every machine
await cache.clear('book:'); // the keys of a prefix, everywhere

How it stays right

  • Versions. Every write carries a version of a hybrid clock (the time of the machine, a counter, the node): two writes of one key on two machines end the same on every machine, the later winning.
  • Deletes and clears are remembered for tombstoneTtl (a minute): a write older than them that arrives late does not bring the value back.
  • Nothing is lost quietly. Each node keeps the writes it sent to each peer until the peer acknowledges them. A broken connection is opened again; the peer says the last write it applied, and the rest is sent. When that is not possible (more writes missed than queue, or a node wrote before it knew of a peer that was there), the peer empties its copy: an empty cache asks the database, a stale one would answer wrong.
  • Warm start. A node that starts gets the entries of its first peer, and start() resolves once the nodes there are connected.
  • Values are kept serialized by v8: Dates, Buffers, BigInts, Maps and Sets come back as they were, and each read is a copy.

API

start(), stop(); get(key), set(key, value, ttl), delete(keys), clear(prefix); size, connected (the ids of the peers connected), stats (sent, applied, ignored, resent, resets, snapshots). Events: peer (id, 'connected' or 'disconnected'), change (a write of another node applied), reset, synced, error.

health({ minPeers }) is a check of xufa.health: down when the cache is not started, degraded when peers it knows are not connected (or fewer than minPeers are), with the peers, those connected, the keys and the writes not acknowledged yet. Not critical by default: a cache that misses asks the database.

With @xufa/orm

The cache of a database: the models with the option cache are read from the copy of the machine, and what one machine saves, updates or deletes, every copy forgets. 

const db = new Database({ backend: 'postgres', url: process.env.DATABASE_URL, cache });

With @xufa/cluster

One NetCache by machine, in the primary; the workers reach it through the bus with the SharedCache of @xufa/orm and its option store:

const { start, bus } = require('@xufa/cluster');
const { SharedCache, Database } = require('@xufa/orm');
const { NetCache } = require('@xufa/netcache');

start({
  primary: async ({ onShutdown }) => {
    const store = await new NetCache({ secret, service: 'shop' }).start();
    new SharedCache({ bus, store }); // the copy of this machine, for its workers
    onShutdown(() => store.stop());
  },
  worker: async () => {
    const db = new Database({ backend: 'postgres', url, cache: new SharedCache({ bus }) });
  },
});

With @xufa/auth

new Lockout({ store: cache }): failed logins are counted on every machine, so an attacker gains nothing by spreading attempts among them.

Faults (tests of resilience)

cache.faults (of @xufa/faults) makes get, set, delete and clear fail, wait or hang (read, write; keys by prefix or regular expression). As the store of @xufa/orm, reads and writes that fail are misses (the database answers, onCacheError is told); deletes that fail are errors. 

cache.faults.down(); // until cache.faults.up()
cache.faults.fail({ operations: 'read', keys: 'session:', rate: 0.1 });

Security

Connections are authenticated with the secret: each side proves it knows it, and the key of each connection is derived from the secret and random values of both sides (HKDF). Every frame is sealed with AES-256-GCM under a counter, so it cannot be read, changed, dropped, reordered or replayed; the discovery of the nodes is sealed with the same secret. Without a secret (insecure: true), any machine of the network can read and write the cache.

What it is not

A cache, not a database: the copies agree within the time a write takes to cross the network, and a counter updated on two machines at the same instant (read, then write) can lose one of the two. Every node holds every key (up to max), so the memory of the cache is that of one machine. Nodes should run the same major version of Node.js (values are serialized by v8).

TypeScript

Declarations included: cache.get<Book>(key) is a Promise<Book | undefined>.
