Sequelize

@xufa/sequelize is the API of Sequelize 6 over xufa's ORM. Code written for Sequelize runs with require('@xufa/sequelize') instead of require('sequelize'), faster, and with no dependencies: PostgreSQL through @xufa/pg, SQLite through node:sqlite.

Switching

npm install @xufa/sequelize
npm uninstall sequelize pg pg-hstore sqlite3
const { Sequelize, DataTypes, Op } = require('@xufa/sequelize'); // was: require('sequelize')

const sequelize = new Sequelize('postgres://user:pass@localhost:5432/db', { logging: false });
const Author = sequelize.define('Author', { name: { type: DataTypes.STRING, allowNull: false } });
const Book = sequelize.define('Book', { title: DataTypes.STRING, pages: DataTypes.INTEGER });
Book.belongsTo(Author, { as: 'author' });
Author.hasMany(Book, { as: 'books' });

await sequelize.sync();
const ada = await Author.create({ name: 'Ada' });
await ada.createBook({ title: 'Notes', pages: 120 });
const books = await Book.findAll({
  where: { pages: { [Op.gte]: 100 } },
  include: [{ model: Author, as: 'author' }],
  order: [['pages', 'DESC']],
});

The tables it makes are those Sequelize makes (names, SQL types, enum types, constraints), so it works on the databases your app already has.

What makes it faster: queries are compiled once per shape and prepared by @xufa/pg (with binary results); rows become instances without copies; belongsTo includes are joins and hasMany ones a query more, so no duplicated rows are put back together; large bulkCreates use COPY. Where the database does the work (updates of many rows, sorts of big tables), the two are about even.

Compatibility

Sequelize's own integration tests (its v6 branch) run against @xufa/sequelize, each file in a process of its own. The same harness runs them against Sequelize 6.37.8 itself, on the same databases, to tell the failures of the tests and of the environment from those of the package (the harness is tools/sequelize-compat). Counted on the tests both runs ran (a test that fails in a hook leaves the rest of its file out, and what a dialect says it supports decides which tests run):

Database (tests run by both)@xufa/sequelizeSequelize 6.37.8
SQLite (1,746)1,720 passed, 21 failed1,737 passed, 4 failed
PostgreSQL 18, with PostGIS, hstore and btree_gist (2,006)1,971 passed, 35 failed1,968 passed, 38 failed

What fails here and passes in Sequelize checks Sequelize's internals (the parsers of its data types, its connection manager and query generator), the exact SQL text it writes, or the differences below, by design; 3 (SQLite) and 8 (PostgreSQL) fail on Sequelize too.

What there is

  • Sequelize: new Sequelize(url, options), new Sequelize(database, username, password, options), new Sequelize(options); dialects postgres and sqlite; define, models, authenticate(), sync({ force, alter, match }), drop(), close(), logging, query() (replacements, binds, types, models).
  • Models: Model.init and define, table names as Sequelize makes them, timestamps, paranoid, indexes, unique, default values, getters and setters, VIRTUAL, scopes, hooks, optimistic locking (version), schemas.
  • DataTypes: STRING, CHAR, TEXT, CITEXT, the integers, BIGINT, FLOAT, REAL, DOUBLE, DECIMAL, BOOLEAN, DATE, DATEONLY, TIME, UUID, JSON, JSONB, BLOB, ENUM, ARRAY, HSTORE, RANGE, GEOMETRY, GEOGRAPHY, INET, CIDR, MACADDR, TSVECTOR.
  • Validation: allowNull, the validators of validator.js that Sequelize has, Validator.extend(), custom and model validators, ValidationError with its items.
  • Finding: findAll, findOne, findByPk, findAndCountAll, count, max, min, sum; every operator of Op; $include.attribute$ keys; literal(), fn(), col(), cast(), where() and json() in conditions, attributes and orders; group, limit, offset, raw, nest, rejectOnEmpty, groupedLimit.
  • Includes: belongsTo (joined), hasMany, hasOne and belongsToMany (a query more each), with where, required, separate (and a limit per parent, done in SQL), nesting, through models, scopes and { all: true }.
  • Writing: build, save, create and bulkCreate (with includes, ignoreDuplicates, updateOnDuplicate), update, destroy, restore, increment, decrement, reload, findOrCreate, upsert.
  • Associations: belongsTo, hasOne, hasMany, belongsToMany, with the keys Sequelize makes, every option, polymorphic associations by scope, and the accessors (getBooks, addBook, setAuthor...).
  • Transactions: managed and not managed, nested as savepoints, isolation levels, row locks, afterCommit, CLS (Sequelize.useCLS()), searchPath. Transactions not managed end with queryInterface.commitTransaction() or rollbackTransaction() (COMMIT; and ROLLBACK; through sequelize.query, logged with the id of the transaction), and one whose end fails is rolled back and its connection closed.
  • Connections: pool.acquire (60 s, then ConnectionAcquireTimeoutError), and connectionManager as Sequelize has it: the numbers of its pool, getConnection() and releaseConnection() (a client of @xufa/pg), validate(), and _connect(), which opens every connection. operatorsAliases, and queryGenerator.handleSequelizeMethod() and getForeignKeysQuery().
  • QueryInterface: createTable, describeTable, addColumn, changeColumn, renameColumn, addIndex, addConstraint, showIndex, rows (bulkInsert, insert, select, upsert, increment, rawSelect...), functions, triggers, databases, enum types... (SQLite tables are made again for the changes it cannot make, as Sequelize does).

PostgreSQL types

  • ARRAY columns are arrays of PostgreSQL, with Op.contains, Op.contained and Op.overlap (JSON in SQLite, where Sequelize has no arrays).
  • HSTORE values are objects of strings, compared as wholes, also in arrays. The database needs the extension hstore.
  • GEOMETRY and GEOGRAPHY are GeoJSON values, with their SRID as crs. The database needs PostGIS.
  • RANGE values are their bounds ([{ value, inclusive }, ...]), as Sequelize gives them, also in arrays.
  • Infinite dates (Infinity, -Infinity) and NaN and infinite floats round-trip.
  • sync adds the values an ENUM gained to its type, in their order.
  • xufa's own fillfactor works as a model option: define(name, attributes, { fillfactor: 50 }).

TypeScript

The declarations are Sequelize's own (6.37.8), ported with their type tests: models typed by InferAttributes and CreationOptional, the accessors of associations, WhereOptions... Left out is what the package has not: the helpers of Sequelize's own SQL writer in Utils and the transactions of the QueryInterface (transactions are sequelize.transaction()). They need no @types/validator, as Sequelize's do. 

import {
  type CreationOptional,
  DataTypes,
  type InferAttributes,
  type InferCreationAttributes,
  Model,
  Sequelize,
} from '@xufa/sequelize';

class User extends Model<InferAttributes<User>, InferCreationAttributes<User>> {
  declare id: CreationOptional<number>;
  declare name: string;
}

const sequelize = new Sequelize('sqlite::memory:');
User.init(
  { id: { type: DataTypes.INTEGER, autoIncrement: true, primaryKey: true }, name: DataTypes.STRING },
  { sequelize }
);
await sequelize.sync();
const ada = await User.create({ name: 'Ada' }); // id is optional

As Sequelize, the package is also an ES module with named exports: import { Sequelize, DataTypes, Op } from '@xufa/sequelize'.

From Sequelize 7

The API is Sequelize 6's: code written for it runs as it is. What Sequelize 7 improves is taken where it does not change what code for Sequelize 6 does:

  • queryInterface.changeColumns(table, { column: definition }): several columns in one ALTER TABLE, changing only what each definition gives (dropDefaultValue: true drops a default). In PostgreSQL an ENUM keeps its type, which gets the values it lacks or is made again when values are left out; a text column can become an enum. changeColumn stays as in Sequelize 6.
  • JSON paths in conditions: keys in double quotes ('data."a.b"'), keys named as operators ({ data: { in: 1 } }), indexes up to 2^31 - 1 and checked casts.
  • Attribute names with any character (first-name, a b, café) in conditions and orders.
  • Attributes computed by the database: DataTypes.VIRTUAL(type, (includeAs) => [literal(...), 'name']), selected when it is in attributes (of the find or of an include), includeAs naming the table of its model in the query.
  • Runtime attributes: with enableRuntimeAttributes: true, the values selected with names of their own ([literal('...'), 'score']) are properties of the instances (user.score).
  • build(saved.toJSON(), { isNewRecord: false }) keeps the timestamps; toJSON() keeps the order of the attributes for virtual ones.
  • BIGINT values as bigints: new Sequelize(url, { bigint: 'bigint' }).
  • Model.findByPks(keys): several primary keys in one query.
  • sync() makes the schemas that are not there.
  • DataTypes.UUIDV7: UUIDs of version 7, in the order they are made.
  • noWait with lock: an error at once on rows locked by others (PostgreSQL).
  • onConflictUpdateWhere, [attribute, value] pairs in updateOnDuplicate (in includes too), and upsert(values, { updateValues }): counters and conditions in ON CONFLICT.
  • Named enums of PostgreSQL: DataTypes.ENUM({ values, name, schema }), one type for many columns.
  • Indexes of foreign keys, when asked: indexForeignKeys: true, or foreignKey: { index }.
  • STRICT tables of SQLite: { strict: true }.
  • Generated columns: generatedAs and generatedColumn (STORED or VIRTUAL).
  • Instances of classes as values (their getters).
  • Plain objects in set/add of associations are created; createTasks(records) creates several.
  • Model.update(values, { include }): the rows whose includes are there.
  • showIndexes(), as Sequelize 7: the name, order and collation of every field, and method and includes in PostgreSQL. showIndex() stays as in Sequelize 6.

Differences

  • BIGINT values are numbers when they are safe integers (bigints otherwise), not strings; the option bigint of the Sequelize instance gives them as bigints ('bigint') or strings ('string', as Sequelize 6 in PostgreSQL), BIGINT keys and the foreign keys to them too.
  • NULLs sort first in ascending order and last in descending order, in every database.
  • hasMany, hasOne and belongsToMany includes are loaded with queries of their own: count with them counts the parents (as distinct: true does), and literals cannot name their columns.
  • A model without a primary key (removeAttribute('id')) has a table without one. Its saved instances cannot be updated, destroyed or reloaded by themselves (Sequelize writes every row of the table then): use Model.update() and Model.destroy().
  • Polymorphic keys are columns, not relations: conditions across them ($comments.title$) are not supported.
  • Right joins (right: true) are not made: right is ignored, as Sequelize does in dialects without them.
  • Geometry coordinates that are not numbers are a ValidationError (PostGIS would store them as 0).
  • Dialects: PostgreSQL and SQLite. MySQL, MariaDB, SQL Server, Oracle and Db2 are not supported.

Moving an app

  1. Replace require('sequelize') (or import ... from 'sequelize') with @xufa/sequelize.
  2. Remove pg, pg-hstore and sqlite3: they are not used.
  3. If your code reads BIGINT values as strings, read them as numbers (or bigints).
  4. If it counts with hasMany includes and distinct: false, check the counts.
  5. Run your tests. Code that reaches into Sequelize's internals (its query generator, connection manager or type parsers) needs another way.
