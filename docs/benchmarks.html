Benchmarks

Each part of xufa against what it replaces, with the same workloads, on the same database and machine. The harnesses are in the repository (bench/), and so are the reports these numbers come from (bench/results/).

How they are measured

  • Every library runs every round in a process of its own, the libraries taking turns, and the median of the rounds is shown (5 rounds unless said).
  • The databases are local servers: PostgreSQL 18 and MongoDB on the same machine, and SQLite in memory.
  • Machine: Intel Core i7-13700H (20 threads), Windows 11, Node.js 22.21.1.
  • ⚠ marks a result whose rounds are more than 10% apart: the machine was busy, so read it as approximate. A Windows desktop is a noisy place to measure; the ratios hold better than the absolute numbers.

Where the database does the work (an update of thousands of rows, a sort of a big table), the libraries are about even: the time is the database's. Where the library does the work (building queries, making objects, the round trips of the driver), xufa is from 2 to 18 times faster. @xufa/sequelize is faster than the ORM's own API at findByPk: it reads one row, where the ORM's get() asks for a few to make sure only one matches (as Django does).

What makes the difference: queries are prepared the second time their text runs, values are read and sent in the binary format, and queries are pipelined, so 64 queries at once do not wait for each other on a connection. For tables updated often, the ORM's fillfactor option helps more than any driver: an update of 5,000 rows went from 10.5 ms to 6.3 ms with fillfactor: 50.

HTTP

Over the network, small responses take about the same time on both: the socket and Node.js's HTTP parser cost about 20 µs a request on this machine, and the framework a few. xufa is clearly ahead on large JSON responses, which it writes as bytes. In the process, most scenarios are ahead or even; hello and post-validate are behind. Run the harness on your machine before deciding: on Linux the loopback is faster and the differences show more.

Run them yourself

git clone https://github.com/xufajs/xufa.git && cd xufa
pnpm install
node bench/orm.js        # the ORM and Sequelize (PostgreSQL and SQLite)
node bench/postgres.js   # @xufa/pg and pg
node bench/mongo.js      # @xufa/mongo and mongodb
node bench/run.js --workers 4   # HTTP over the loopback
node bench/inproc.js     # HTTP in the process

The database benchmarks use postgres://xufa:xufa@127.0.0.1:5432/xufa_test and mongodb://127.0.0.1:27017/xufa_bench by default (--url to change them), and drop the tables and collections they make. bench/README.md explains every option and how to read the results.
