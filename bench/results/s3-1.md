# S3 clients: @xufa/orm's s3 backend against the AWS SDK v3

`XUFA_S3_URL=http://xufa:xufa-secret-key@localhost:8333/xufa-test node bench/micro/s3.js 2` (BENCH_TIME=1000), on
SeaweedFS 4.48 in WSL 2 (Ubuntu) on the same laptop (13th Gen Intel Core i7-13700H, 20 cores, Windows 11, Node.js
v22.21.1), 2026-10-07. 16 requests at a time, objects of 1 KiB, the best of 2 rounds; each client and operation in a
process of its own. The store and the network weigh more than the clients: compare them with each other.

| Operation                         | xufa ops/s | aws-sdk ops/s | xufa / aws-sdk |
| --------------------------------- | ---------: | ------------: | -------------: |
| PUT 1 KiB (and HEAD for its info) |      1,755 |         1,102 |           1.59 |
| GET 1 KiB                         |      3,760 |         1,180 |           3.19 |
| HEAD                              |      4,177 |         1,278 |           3.27 |
| DELETE (and PUT again)            |      1,291 |           595 |           2.17 |
| list 100 keys                     |      1,049 |           569 |           1.84 |

Before this run the backend used Node's fetch: PUT 477, GET 2,299, HEAD 747, DELETE 372, list 925 a second (fetch
is several times slower than node:http with connections kept for small requests, HEAD above all). It now sends its
requests with node:http(s) and a keep-alive agent (packages/orm/lib/backends/blob/http-client.js).
