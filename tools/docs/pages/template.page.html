@xufa/template

Templates of text and HTML with the safe expressions of @xufa/expression: values escaped for HTML, blocks, filters, partials, layouts and streaming, compiled once and rendered many times. With the plugin, reply.view() renders the views of a folder in @xufa/http (and fastify). It renders faster than Handlebars, Mustache, Nunjucks and even Eta and EJS, which run the JavaScript of their templates. No dependencies outside xufa.

Quick start

npm install @xufa/template   # or require('xufa/template')
const { compile, render } = require('@xufa/template');

const page = compile(`
<h1>{{ title | upper }}</h1>
<ul>
  {{~#each items as item~}}
  <li class="{{ loop.first ? 'first' : '' }}">{{ item.name }}: {{ item.price | number('en-US', { style: 'currency', currency: 'USD' }) }}</li>
  {{~else~}}
  <li>Nothing yet</li>
  {{~/each~}}
</ul>
{{#if user}}Hello, {{ user.name }}{{else}}<a href="/login">Log in</a>{{/if}}`);

page({ title: 'Books', items, user });
render('Hello {{ name }}', { name: '<Ada>' }); // 'Hello &lt;Ada&gt;'

Values

TagWrites
{{ expression }}The value, escaped for HTML.
{{{ expression }}}The value as it is.
{{ value | filter(args) | other }}The value through filters.

Expressions are those of @xufa/expression: {{ items.map(i => i.name).join(', ') }}, {{ `${count} items` }}, {{ user?.name ?? 'guest' }}. In templates they are lenient: a name that is not there, or a member of null, is nothing (strict: true makes them errors). null and undefined are written as nothing, lists and plain objects as JSON, the rest as text.

if

{{#if cart.items.length > 10}}
  <p>Free shipping!</p>
{{else if cart.items.length > 0}}
  <p>{{ 10 - cart.items.length }} more for free shipping</p>
{{else}}
  <p>Your cart is empty</p>
{{/if}}

each

{{#each orders as order, i}}
  <tr class="{{ loop.last ? 'last' : '' }}"><td>{{ loop.number }}</td><td>{{ order.id }}</td></tr>
{{else}}
  <tr><td>No orders</td></tr>
{{/each}}

{{#each settings as value, key}}{{ key }}={{ value }} {{/each}}

Lists, strings, iterables, Maps and plain objects (the second name is the index or the key; item is the name when none is given). loop has index, number (from 1), first, last, length and key. {{else}} is rendered when there is nothing. Inside, the names around the block are still there.

with

{{#with order.customer.address as address}}{{ address.street }}, {{ address.city }}{{/with}}

Partials

const engine = new TemplateEngine({ partials: { card: '<div class="card">{{ name }}</div>' } });
engine.partial('row', '<tr><td>{{ item.name }}</td></tr>');
engine.render('{{#each items as item}}{{> row}}{{/each}}{{> card user}}', { items, user });

{{> name}} renders a partial with the context; {{> name value}} with the properties of the value over it. Partials can be recursive (trees), up to maxDepth (32). With the plugin, partials are files of the folder: {{> partials/header}}.

const engine = new TemplateEngine({ filters: { money: (value) => `${value.toFixed(2)} €` } });
engine.filter('initials', (name) => name.split(' ').map((part) => part[0]).join(''));
engine.render('{{ total | money }} by {{ user.name | initials }}', { total: 12, user: { name: 'Ada Lovelace' } });

reply.view

The plugin renders views, files of a folder, as @fastify/view does, on @xufa/http or fastify: 

const xufa = require('xufa');
const template = require('xufa/template');

const app = xufa();
app.register(template.plugin, { root: 'views', layout: 'layout', defaultContext: { site: 'Books' } });
app.addHook('preHandler', async (request, reply) => {
  reply.locals = { user: request.user }; // in the context of every view of the request
});
app.get('/books/:id', async (request, reply) => reply.view('books/show', { book: await findBook(request.params.id) }));

const html = await app.view('emails/welcome', { user }); // the text, for emails
DecorationWhat it does
reply.view(name, data, { layout, stream })Renders <root>/<name>.html and sends it as text/html, unless the reply has a content type.
reply.viewAsync(...), app.view(...)The text.
reply.localsNames for the views of the request, set in hooks.

The context of a view is defaultContext, then reply.locals, then the data. A name that leads out of root (.., an absolute path, in views and partials) is refused, so a view named by a request cannot read other files; a view that is not there, or fails, is an error (500) that names its template, line and column.

Layouts

<!-- views/layout.html -->
<!doctype html>
<html><head><title>{{ title ?? site }}</title></head>
<body>{{> partials/nav}}<main>{{ body }}</main></body></html>

The view is rendered first and given to its layout as body. The layout of the plugin, or of a call; layout: false for none.

Large pages

reply.view(name, data, { stream: true }), or stream: true for every view, sends the view in chunks made as the client reads them: the first bytes go at once, and the page is never whole in memory. The layout is cut where it writes {{ body }}: its head goes first, then the chunks of the view, then its tail. A page of 200,000 rows (20 MB) sends its first byte in 2 ms instead of 265, ends in 127 ms instead of 286, and takes 3 MB of memory instead of 40 (Benchmarks). 

app.get('/report', (request, reply) => reply.view('report', { rows: allRows }, { stream: true }));

for (const chunk of compile(source).stream(context, { chunkSize: 16384 })) socket.write(chunk); // any template

The files are read and compiled before anything is sent, so a view that is not there is still a 500; an error while the view renders cuts the response (its status is sent already). A layout that writes its body otherwise (twice, or through a filter) is rendered whole.

Data with templates

const config = fill(
  {
    host: '{{ env.DB_HOST }}',
    port: '{{ Number(env.DB_PORT ?? 5432) }}',
    url: 'postgres://{{ env.DB_HOST }}/app',
    replicas: '{{ (env.REPLICAS ?? "").split(",").filter(Boolean) }}',
  },
  { env: process.env }
); // { host: 'db', port: 5432, url: 'postgres://db/app', replicas: ['r1', 'r2'] }

fill(value, context) fills the strings of data (configuration, messages) without escaping: a string that is one {{ expression }} alone gives its value (a number, a list, an object), the others their text; arrays and plain objects are filled item by item, and a key __proto__ of JSON stays a key.

Escaping

& < > " ' and the backtick are escaped, which makes values safe in the text of elements and in quoted attributes; not in <script>, in style, nor in URLs (href="{{ url }}" with javascript:...): check those values before they go there. escape: false (an engine, or one call) writes values as they are, and a function of your own escapes for other formats. new SafeString(html) marks text that is HTML already.
