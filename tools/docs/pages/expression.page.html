@xufa/expression

Expressions of JavaScript, a safe part of it, compiled once and run many times on data of their own: rules, formulas, conditions and templates that users or configuration write. They read the data they are given and nothing else, cannot assign, and cannot reach the process, prototypes or constructors. Compiled to closures, and to JavaScript when they run often, they run at up to 140 million times a second, 8 to 850 times as fast as other sandboxed evaluators (the fastest of them in each case). No dependencies.

Quick start

npm install @xufa/expression   # or: import from 'xufa/expression'
import { compile, evaluate } from '@xufa/expression';

const items = [
  { name: 'Pen', price: 5, quantity: 3 },
  { name: 'Book', price: 12, quantity: 2 },
  { name: 'Lamp', price: 30, quantity: 1 },
];
const user = { name: 'Ada', tags: ['admin', 'author'] };

const total = compile('items.filter(i => i.price > min).reduce((sum, i) => sum + i.price * i.quantity, 0)');
console.log(total({ items, min: 10 })); // compiled once, run as often as you like

console.log(evaluate('user.name?.toUpperCase() ?? "anonymous"', { user }));
console.log(evaluate('`${user.name} has ${user.tags.length} tags`', { user }));
try {
  evaluate('user.constructor', { user });
} catch (err) {
  console.log(err.code); // what is not data is out of reach
}

What it is for

  • Rules and conditions stored in a database or written by users: order.total > 100 && customer.country === 'ES'.
  • Formulas of a spreadsheet, a pricing table, a report.
  • Mappings and transformations of data, in configuration: row.items.map(i => ({ sku: i.code, qty: i.n })).
  • Templates: @xufa/template is made with it.

Where new Function or node:vm would run any code (and vm is not a security boundary), an expression runs only what the language below allows, on the data you give it.

API

FunctionWhat it does
compile(source)A function of the context: fn(context) gives the value. Kept by its source (the next compile of the same text is free). fn.source is its text.
evaluate(source, context)compile(source)(context).
parse(source, { filters })The tree (nodes as those of ESTree: BinaryExpression, MemberExpression...).
new Engine(options)An engine of its own, with options: compile, evaluate, parse. The module's functions use a default one.
ExpressionError, GLOBALS, FORBIDDEN, locate(source, position)The error class, the default globals, the names that cannot be reached, and the line and column of a position.

The context is an object whose properties are the names of the expression (it can be a class instance, with getters). Names that are not there are undefined (strict makes them errors).

Arrow functions

evaluate('items.map((item, i) => item.price * i)', { items });
evaluate('orders.filter(o => o.total > 100).map(o => ({ id: o.id, vip: o.total > 1000 }))', { orders });
evaluate('[1, 2, 3].map(x => [4, 5].map(y => x * y))'); // nested, with the names around them

With an expression body (an object in parentheses). They are functions of JavaScript, so array methods, JSON.parse revivers and the functions of your context can call them.

What is not there

An expression is one expression. These are not allowed in it:

  • Statements: let, const, if, loops, return, labels.
  • Assignments: =, += and the rest, ++, --.
  • new, this, delete, void, instanceof and the comma operator ((a, b)).
  • function, class, async and await, generators, import and export.
  • Methods, getters and setters in object literals, and holes in arrays ([1, , 2]).
  • Destructuring in the parameters of arrow functions (([a, b]) => a).
  • Comments and tagged templates.

Each is a syntax error with its line and column. Arrow functions, spread, templates, optional chains, regular expressions and in are allowed.

Engines of programs (statements: true) allow all of this list. The one exception is this, which works only in the methods of classes and objects.

Programs

An engine with statements: true compiles programs: the code of rules, methods and scripts that need more than one expression, with the same safety. 

import { Engine } from '@xufa/expression';

const engine = new Engine({ statements: true });
const total = engine.compile(`
  let total = 0;
  for (const line of order.lines) {
    if (line.quantity > 10) total += line.price * line.quantity * 0.9; // bulk
    else total += line.price * line.quantity;
  }
  return Math.round(total * 100) / 100;
`);
const order = { lines: [{ price: 2.5, quantity: 20 }, { price: 10, quantity: 1 }] };
console.log(total({ order }));
console.log(engine.evaluate('x = x + 1\nx * 2', { x: 5 })); // the value of the last statement

Private members (#count, #bump(), get #total(), static #made, #count in other) are those of the class that declares them, read only on objects of that class (node?.#next too).   • More globals: BigInt, String.raw, Array.from, Array.of, structuredClone, and Object.assign and Object.freeze of what a program can change. Arrays made of a length have at most 10 million items.
  • The value of a program is that of its return, or of the last expression statement it ran. A program of one expression is that expression, compiled and made fast as one.
  • Names are variables of the program, never the context: a name assigned and declared nowhere is a variable of the program that starts with the value of that name in the context. A program changes members only of plain objects and arrays (those of its context too, as a function of JavaScript can), never of the globals or what they reach (Math.max = ...), of functions, dates or instances of classes, nor by the names __proto__, constructor and prototype.
  • new makes only what constructors names (Date, Map, Set, Array, Error, TypeError, RangeError).
  • Loop turns and calls of its functions count, those of arrow functions given to map, filter, sort... too (in engines of expressions as well): past maxSteps (10 million) a program fails with XUFA_EXPR_ERR_LIMIT, and so it does with calls nested deeper than maxDepth (1000). No catch of the program stops those errors.
  • Generators (function*, *method(), yield, yield*), async generators and for await; their turns count as steps.
  • Modules: import (default, named, renamed, * as ns) and export at the top of programs. The modules option resolves a name to the source of a module (run for each import, with a context of its own) or to an object the host exports (a frozen copy); cycles and exports a module lacks are refused. A { that starts a statement is a block.

Trees of other languages

engine.compileTree(tree, source, { bound }) compiles a tree made by another parser (of another language, as the language of OpenL in @xufa/rules), with the nodes parse() gives: the checks are those of the compiler, not of the parser. What the parser never makes is refused first (XUFA_EXPR_ERR_FORBIDDEN): names, properties, keys and names of variables, parameters, constructors or filters that are not strings, literals that are objects or functions, trees that refer to themselves, and nodes that are not plain objects or arrays. bound are names of that tree whose values are fixed, over the context (the option bound of an engine, of all its trees): what the language needs (its functions, its helpers) without a context that could hide them.

What an expression can reach

The context it is given, the parameters of its arrow functions, and its globals. It cannot:

  • read __proto__, constructor, prototype, caller, callee, arguments or the old accessors of Object.prototype (__defineGetter__...), by name or computed: x['__pro' + 'to__'] is refused when it runs, and a key is turned to text once, so an object whose toString changes its answer cannot slip one by (XUFA_EXPR_ERR_FORBIDDEN). So no expression reaches Function, and with it the process;
  • assign anything, so it cannot change its context nor the prototypes of the process; the objects it makes have their keys as their own properties (__proto__ cannot be a key, and { ...JSON.parse(...) } keeps a key __proto__ as a key);
  • reach process, require, globalThis, timers or modules: they are not names it has.

The functions you put in the context are called as they are: what they can do, the expression can make them do.

Globals

Math; JSON (parse, stringify); Number, String and Boolean as conversions with their static helpers (Number.isInteger, String.fromCharCode...); Array.isArray; Object.keys, values, entries and fromEntries; Date.now and Date.parse; parseInt, parseFloat, isNaN, isFinite, the URI functions, Infinity and NaN. Nothing that writes: no Object.assign, Object.defineProperty, Array.from. 

const pricing = new Engine({ globals: { tax: (v) => v * 1.21, round: (v, d) => +v.toFixed(d) } });
pricing.evaluate('round(tax(order.total), 2)', { order }); // the context goes over the globals

Limits

An expression has no loops of its own, so its time and memory follow from its length and its data; but a method can still make a large value ('x'.repeat(1e9), a map of a large list). For expressions of people you do not trust: give contexts of data (not objects of your application with methods), keep maxLength small, and run them where a slow one does not hold others (a worker with a time limit).

Filters

const engine = new Engine({ filters: { round: (v, d) => +v.toFixed(d), money: (v) => `${v} €` } });
engine.evaluate('price * quantity | round(2) | money', { price: 1.234, quantity: 3 }); // '3.7 €'
engine.evaluate('(a || b) | round(1)', { a: 0, b: 2.25 }); // filters in parentheses too

The value goes first, then the arguments. With filters, | is not the bitwise or.

How it runs

  1. The source is read by a parser of its own (no eval, no acorn) into a tree, refused when it has what the language has not.
  2. The tree becomes closures, one for each node, made once: the names and keys that cannot be reached are refused here.
  3. After inlineAfter runs, the expression (or the program: its statements those of JavaScript, its names variables made for them, its steps, depth and changes of members checked by helpers) becomes one function of JavaScript, whose arrow functions are arrow functions of JavaScript, and V8 compiles it as your code. Nothing of the source is code in it: strings, names and keys are JSON literals, numbers are written by String(), operators come from a fixed list, parameters get names of their own, and what must be checked (names, members, calls, computed keys, optional chains) is checked there as in the closures, with the same errors. With code generation off (--disallow-code-generation-from-strings), the closures go on.

Method calls run at 88% of the speed of JavaScript, map and reduce at 71%. Every expression is in Benchmarks; node bench/micro/expression.js measures them.

Programs (statements: true) become one function of JavaScript too: 4 to 134 million runs a second for branches, switches, loops and functions, from a third of the speed of JavaScript itself to as fast, and 140 to 2,200 times that of SandboxJS, the other sandbox that runs statements (5 times with exceptions thrown). Compiling one takes about 10 microseconds. Every program is in Benchmarks; node bench/micro/expression-programs.js measures them.

The two ways are kept the same by a fuzz: random programs of every statement and feature run on the closures, on the function and as JavaScript itself, with the same values and the same errors. Run it longer, with other seeds, with node packages/expression/test/fuzz/run.js --random --count 100000.
