@xufa/admin

The admin of the models of @xufa/orm, as Django's: a page with the list of each model (search, filters, order, pages) and its forms (from its fields, with the errors of its validation), for every backend of the ORM, as a plugin of @xufa/http. No dependencies, and no build: the page is one document with its script.

Quick start

const xufa = require('@xufa/http');
const { Database, Model, fields } = require('@xufa/orm');
const { admin } = require('@xufa/admin');

class Author extends Model {
  static fields = { name: fields.string(), country: fields.string({ null: true, choices: ['ES', 'UK', 'US'] }) };
}
class Book extends Model {
  static fields = { title: fields.string(), pages: fields.integer({ null: true }), author: fields.foreignKey(() => Author) };
  toString() {
    return this.title; // how a book is shown (as Django's __str__)
  }
}
const db = new Database({ backend: 'memory' }).register(Author, Book);
await db.sync();

const app = xufa();
app.register(admin, {
  prefix: '/admin',
  models: [Book, [Author, { search: ['name'] }]],
  authorize: (request) => true, // who may use it: required (request.user?.role === 'staff'...)
  title: 'Bookshop',
});

const page = await app.inject('/admin/');
console.log(page.statusCode, page.headers['content-type']); // open /admin/ in a browser
200 text/html; charset=utf-8

Lists

Each model has a list: the columns of list (the first six fields that are not text nor json), a search in the fields of search (its string fields), filters by the fields of filters (booleans, choices and foreign keys), an order by any column (a click on it), and pages of 25. The objects of foreign keys are shown by their labels. 

app.register(admin, {
  prefix: '/admin',
  models: [[Book, { list: ['title', 'author', 'published'], search: ['title', 'isbn'], filters: ['published'] }], Author],
  authorize,
});
Option of a modelWhat it is
labelThe name shown
list, search, filtersIts columns, the fields its search looks in, the fields it filters by
readOnlyFields shown in its forms but not changed (besides keys, automatic dates and fields given by the backend)
readOnlyModelOnly shown: no creates, updates nor deletes

Forms

A form has an input for each field: text, numbers, checkboxes, dates and times, the choices of a field, a select of the objects of a foreign key, JSON. The required ones are marked; keys, automatic dates and readOnly fields are shown, not changed. Saving runs the validation of the model (its fields, its rules, its unique values), and its errors are shown by field. A delete is that of the model: with softDelete, the object is kept with its date.

Pipeline runs and health

app.register(xufa.health, { checks: { database: db.health(), queue: queue.health() } });
app.register(admin, { prefix: '/admin', models: [Book], pipelines, authorize });
  • Health: with xufa.health registered, the first page shows its report: the status of the app and each check with its time and its error or details (health: false leaves it out).
  • Runs: with pipelines (a Pipelines of @xufa/queue), the page lists their runs (by status and pipeline, newest first) and shows each run: the graph of its steps in columns by depth, colored by status (a skipped one dashed), with arrows; the step chosen with its block, attempts, times, the end of its wait (pausedUntil), its output and its error; the input and the result of the run. A run that runs is read again every 3 seconds.
  • Pipelines in pipelines: a step of the block pipeline links to the run it started, and that run to the run and step that started it.
  • Actions: Retry (a failed or cancelled run goes on from where it stopped), Cancel (a running one), and Resume of a paused step with its output, as JSON.

Who may use it

Its login page: with login, the admin has a page of its own to log in (GET login, POST login, POST logout) built on @xufa/auth and @xufa/session (registered before the admin): 

app.register(sessionPlugin, { secret: process.env.SESSION_SECRET, store: ormStore(db), csrf: true });
app.register(admin, {
  prefix: '/admin',
  models: [Book, Author],
  login: {
    findUser: (email) => User.objects.filter({ email: email.toLowerCase() }).first(),
    allow: (user) => user.role === 'staff', // who may use the admin
    totp: (user) => user.totpSecret, // a code of an authenticator app after the password (optional)
    lastTotpStep: (user) => user.totpStep,
    onTotp: (user, step) => User.objects.filter({ pk: user.pk }).update({ totpStep: step }),
    rehash: (user, hash) => User.objects.filter({ pk: user.pk }).update({ password: hash }),
  },
});
  • Passwords are the hashes of auth.hashPassword() (user.password, or password(user)), checked in constant time; a user that is not there takes the same time, and wrong users, wrong passwords and users that allow refuses get the same answer.
  • Failures lock out: 5 by user in 15 minutes (lockout), 20 by address (ipLockout, so an office behind one address is not locked for a few typing errors); a Lockout of @xufa/auth with a shared store counts them for every worker. Locked attempts get 429 with Retry-After.
  • With totp, the page asks for the code only once the password was right; each code works once (lastTotpStep, onTotp).
  • The user logged in is kept in the session, whose id changes at the login; logging out ends it. Without a user, the page goes to the login page and the API answers 401. The page sends the CSRF token of the session with its writes, so sessions with csrf: true work.
  • authorize, given too, is asked after the login, with request.adminUser ({ id, name }).

Or your own check: authorize(request, reply) is asked for every request of the admin (the page and its API), and is required without login: 'development' lets in every request while NODE_ENV is not production. With @xufa/auth, register the admin after it and look at request.user. Writes need the header the page sends (x-xufa-admin: 1): a form of another site cannot send it (browsers ask the server first), so they need no CSRF token.

Its API

The page uses an API of its own, under the prefix (it can be used by scripts too, with the header for writes):

RouteWhat it does
GET api/modelsThe models: their fields, lists, searches, filters and counts
GET api/:modelA page of objects: ?search=, ?filter.<field>=, ?order=-pages, ?page=, ?size=
GET api/:model/:pkAn object: its values, label and the labels of its foreign keys
POST api/:model, PATCH api/:model/:pkCreates and updates (400 with errors by field; 409 for unique values)
DELETE api/:model/:pkDeletes (409 when protected)
GET api/:model/choicesKeys and labels of the objects of a model (for selects of foreign keys), ?search=
GET api/_runsThe runs of the pipelines: ?status=, ?pipeline=, ?page=; the counts by status and the names of the pipelines
GET api/_runs/:idA run: its input, result, error, the graph of its definition and its steps
POST api/_runs/:id/retry, /cancel, /steps/:step/resumeThe actions (resume takes { output }); 409 when the run or step is not in a state for them
GET api/_healthThe report of xufa.health, its checks run now (404 without it)
