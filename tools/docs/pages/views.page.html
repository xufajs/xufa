@xufa/views

Views of classes, as Django's generic views: a class says what a page is (its model, its fields, its template, its pages) and its methods do the rest: the list of a model in pages, an object (404 when it is not there), the forms that create and update it (a ModelForm of its fields, checked by the model) and the question before it is deleted. Each request makes its own view; a method of the class changes one step. Templates are those of @xufa/template.

Quick start

import xufa from '@xufa/http';
import * as template from '@xufa/template';
import { ListView, DetailView, CreateView } from '@xufa/views';

class BookList extends ListView {
  static model = Book;
  static templateDir = 'catalog'; // catalog/book_list
  static paginateBy = 2;
}

class BookDetail extends DetailView {
  static model = Book; // catalog/book_detail, with book (and object)
  static templateDir = 'catalog';
}

class BookCreate extends CreateView {
  static model = Book; // catalog/book_form, with form
  static templateDir = 'catalog';
  static fields = ['title', 'isbn'];
}

const app = xufa();
app.register(xufa.formBody);
app.register(template.plugin, { root });
app.route(BookList.asRoute('/catalog/books/', { name: 'books' }));
app.route(BookDetail.asRoute('/catalog/book/:pk', { name: 'book-detail' }));
app.route(BookCreate.asRoute('/catalog/book/create/', { name: 'book-create' }));

console.log((await app.inject('/catalog/books/?page=2')).body);
console.log((await app.inject('/catalog/book/2')).body, (await app.inject('/catalog/book/99')).statusCode);
const made = await app.inject({ method: 'POST', url: '/catalog/book/create/', payload: { title: 'Walden', isbn: '4' } });
console.log(made.statusCode, made.headers.location);
const again = await app.inject({ method: 'POST', url: '/catalog/book/create/', payload: { title: 'Copy', isbn: '4' } });
console.log(again.body.includes('Book with this ISBN already exists.'));

Settings

The settings of a view are static fields of its class (Django's attributes of a class): those of the classes it extends, the nearest first. A view is made for each request with them as its own values (this.model, this.paginateBy; pagination: 'keyset' pages a ListView by keys, ?cursor=, with page.nextCursor and page.previousCursor: the KeysetPaginator of the ORM), and asView(options) changes them for one route: BookList.asView({ paginateBy: 50 }). A name that is not a setting of the class is an error when the route is made, not when it is asked.

Routes

View.asView(options) gives the handler of a route; View.asRoute(url, routeOptions, options) the whole route for app.route(), with the methods the view answers (View.methods: GET for lists and details, GET, POST and PUT for forms, GET, POST and DELETE for deletes; HEAD comes with GET). A method the view does not answer is a 405 with Allow. As Django's, a parameter can say what it is: /catalog/book/<int:pk>.

The pages of a model

crud(Model, options) gives the five routes of a model, named as the Django tutorial names them, for app.route() (or a crud: entry of an app's urls.yaml):

NamePathViewPermission
books/books/ListView
book-detail/book/<int:pk>DetailView
book-create/book/create/CreateViewBook.add
book-update/book/<int:pk>/update/UpdateViewBook.change
book-delete/book/<int:pk>/delete/DeleteViewBook.delete
 
import { crud } from '@xufa/views';

for (const route of crud(Book, {
  prefix: '/catalog',
  templateDir: 'catalog',
  fields: ['title', 'author', 'summary', 'isbn', 'genre'],
  list: { selectRelated: 'author' },
  detail: { prefetchRelated: ['genre', 'bookInstanceSet'] },
  delete: { blockedText: "You can't delete this book until all copies have been deleted:" },
})) {
  app.route(route);
}

The key's converter comes from the model (<uuid:pk> for a uuid). Each page takes the settings of its view, view (a class of its own), selectRelated and prefetchRelated (its queryset) and path. only keeps some pages, permissions: false drops the permissions (or { update: 'Book.edit' } changes one), name and plural change the names. The forms go to the page of the object, and the delete to the list.

Built-in templates

A view of a model renders its template (catalog/book_list.html), or, when the app has none (app.hasView() of @xufa/template), a built-in one: xufa/list, xufa/detail (the fields of the object by their labels), xufa/form and xufa/confirm_delete, of the folder templates this package exports. They extend the app's base template ({{extends baseTemplate}}, filling its block content) and show title: Book List, Book: Dune, Create book, Update book: Dune, Delete book, made of the model's label (static options = { label: 'book copy' }; 'book instance' of BookInstance by default). static title changes it ('Delete Author: {lastName}'). An app's template of the same name, xufa/form.html, takes the place of the built-in one. 

import * as views from '@xufa/views';

app.register(template.plugin, { root: ['templates', views.templates] }); // the app's first
app.register(views.plugin, { baseTemplate: 'base_generic', paginateBy: 10 }); // app.viewDefaults

views.plugin gives the defaults of the views of the app: baseTemplate ('base') and paginateBy of the lists that give none. A project does both from its views: key.

Who may come

static loginRequired = true and static permissionRequired = 'Book.add' (or a list) are Django's LoginRequiredMixin and PermissionRequiredMixin, with the accounts of @xufa/auth: without a user, to the login page with ?next= (401 for JSON clients); without the permission, a 403 the error handler of the app shows.

ListView

The objects of its QuerySet (model, or queryset; ordering) in its template (templateName, or <templateDir>/<model>_list), as objectList and <model>List (bookInstanceList; or contextObjectName). With paginateBy (else the app's; false: none), in pages of the Paginator: the page of ?page= (or the parameter page of the route; last is the last one), with page, paginator and isPaginated in the context; a page that is not there is a 404. paginateOrphans, and allowEmpty: false (an empty list is a 404).

DetailView

The object of the route: its key (:pk, pkUrlKwarg), or its slug (:slug, slugField), of the QuerySet, as object and <model>, in <model>_detail. Not there (or a key the model cannot have) is a 404: getObjectOr404(Book, { pk }) and getListOr404() are Django's shortcuts for views of functions.

Create and update

CreateView and UpdateView show a form (formClass, or a ModelForm of fields) in <model>_form: GET with the values of the object (or initial), POST cleans it; with errors, the form again (status 200); valid, the object saved and to successUrl ('/catalog/book/{id}' fills the fields of the object), or to the address of the object (its absoluteUrl or getAbsoluteUrl()). FormView is the same with a form of its own and no object. 

class AuthorCreate extends CreateView {
  static model = Author;
  static fields = ['firstName', 'lastName', 'dateOfBirth', 'dateOfDeath'];
  static initial = { dateOfDeath: '2023-11-11' };
  static permissionRequired = 'Author.add';
}

DeleteView

GET asks (<model>_confirm_delete, with the object and question), POST deletes it and goes to successUrl (DELETE does it at once). The objects others keep pointing to it with (onDelete: 'protect') are blockers in the context, [{ object, href, text, relation }], with blockedText: the page lists them instead of the button. A POST they stop (the ProtectedError of the ORM) comes back to the page, as Django's views that catch it. 

class AuthorDelete extends DeleteView {
  static model = Author;
  static permissionRequired = 'Author.delete';
  static question = 'Are you sure you want to delete {firstName} {lastName}?';
  static blockedText = "You can't delete this author until all their books have been deleted:";

  getSuccessUrl() {
    return this.reverse('authors');
  }
}

Changing them

Each step is a method, as Django's: getQueryset(), getObject(), getContextData(context) (async: what the template gets more), getTemplateNames(), getForm(), getFormKwargs(), getInitial(), getSuccessUrl(), formValid(form), formInvalid(form), renderToResponse(context). In them, this.reverse(name, params) gives the address of a named route. 

class LoanedBooksByUser extends ListView {
  static model = BookInstance;
  static templateName = 'catalog/bookinstance_list_borrowed_user';
  static paginateBy = 10;
  static loginRequired = true;

  getQueryset() {
    // Not async (a QuerySet is thenable); after loginRequired, request.account is the user.
    return BookInstance.objects.filter({ borrower: this.request.account.pk, status: 'o' }).orderBy('dueBack');
  }
}

class AuthorDetail extends DetailView {
  static model = Author;

  async getContextData(context) {
    const books = await this.object.bookSet.annotate({ copies: Count('bookInstanceSet') });
    return super.getContextData({ ...context, books });
  }
}

Related objects a template only lists need no code: static queryset = Book.objects.prefetchRelated('genre', 'bookInstanceSet'), and the template reads them from the object ({{#each book.bookInstanceSet as copy}}, {{ book.genre | join }}).

404 and errors

Http404 (status 404) is what is not there; the error handler of the app shows its page. ImproperlyConfigured is a view not set up for what it is asked (no model, no fields for a ModelForm, no successUrl and no address of the object): a mistake of the code, a 500.
