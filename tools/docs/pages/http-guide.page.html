Guide

This guide builds an app with @xufa/http, from the first route to running it in production. Its API is fastify's, so what you know of fastify holds; what xufa does differently is marked, and gathered in From fastify. Every option and method is in the API.

Getting started

npm install @xufa/http
// server.js
import xufa from '@xufa/http';

const app = xufa({ logger: true });

app.get('/', async () => ({ hello: 'world' }));

app.listen({ port: 3000 }).catch((err) => {
  app.log.error(err);
  process.exit(1);
});

xufa(options) makes an app (an instance). A route is a method, a path and a handler; an async handler returns what the reply is, and an object is sent as JSON. logger: true logs each request and its reply as JSON lines (Logs). 

$ node server.js
{"level":30,"time":1759834512345,"pid":4120,"hostname":"dev","msg":"Server listening at http://127.0.0.1:3000"}
$ curl localhost:3000
{"hello":"world"}

listen() listens on localhost by default. In a container, listen on every interface: app.listen({ port: 3000, host: '0.0.0.0' }).

The layout of an app

Make the app in a function, and listen in another file: tests then make the app without listening (Testing), and the parts of the app are plugins (Plugins). 

// app.js: the app, without listening.
import xufa from '@xufa/http';
import db from './plugins/db.js';
import books from './routes/books.js';
import users from './routes/users.js';

function build(options = {}) {
  const app = xufa(options);
  app.register(db);
  app.register(books, { prefix: '/books' });
  app.register(users, { prefix: '/users' });
  return app;
}

export { build };

// server.js: the app, listening.
import { build } from './app.js';

const app = build({ logger: true });
app.listen({ port: Number(process.env.PORT) || 3000, host: '0.0.0.0' });
// routes/books.js: a plugin with the routes of books.
export default async function books(app) {
  app.get('/', async () => app.db.books.list());
  app.get('/:id', async (request) => app.db.books.get(request.params.id));
};

Routes

app.get, head, post, put, delete, options, patch, trace and all take a path, options (optional) and a handler. app.route() takes them as one object. 

app.get('/books', async () => listBooks());
app.get('/books/:id', { schema: { params: BookId } }, async (request) => getBook(request.params.id));

app.route({
  method: ['PUT', 'PATCH'],
  url: '/books/:id',
  schema: { params: BookId, body: BookPatch },
  handler: async (request) => updateBook(request.params.id, request.body),
});

Paths have parameters, wildcards and regular expressions, as find-my-way has them (written as they are in a JavaScript string, so the \d of a regular expression is \\d):

PathMatchesrequest.params
/books/:id/books/42{ id: '42' }
/books/:id/pages/:page/books/42/pages/7{ id: '42', page: '7' }
/files/*/files/a/b.txt{ '*': 'a/b.txt' }
/books/:id(^\\d+)/books/42, not /books/x{ id: '42' }
/at/:hour(^\\d{2})h:minute(^\\d{2})m/at/09h30m{ hour: '09', minute: '30' }
/books/:id?/books and /books/42{}, { id: '42' }

Parameters are texts; a schema of params converts them (Validation). A GET route answers HEAD too (exposeHeadRoutes). Routes can also be told apart by version or host (constraints: { version: '2.0.0' }, { host: 'api.example.com' }), or by a strategy of your own (addConstraintStrategy).

The options of a route that are used most:

OptionWhat it does
schemabody, querystring, params, headers validated; response by status, serialized
onRequest, preHandler... Hooks of this route only (Hooks)
configValues of the route, read by hooks and plugins as request.routeOptions.config (@xufa/auth reads config.auth)
bodyLimitThe largest body, in bytes (1 MiB by default)
handlerTimeoutms the handler may take: then a 503, and request.signal aborts
logLevelThe level of the logs of this route ('warn' to quiet a health check)
errorHandlerThe error handler of this route
attachValidationInvalid requests reach the handler, with request.validationError
nameThe name of the route, for app.reverse() (Names of routes)

Names of routes

A route with a name gives its address back with app.reverse(name, params, { query }), as Django's reverse(): links are written once, by name, and follow the routes when their paths or the prefixes of their plugins change. The parameters go by name or in order; a parameter with a regular expression must match it, and values are encoded (a * keeps its slashes). 

app.register(
  async (catalog) => {
    catalog.get('/book/:id(^\\d+$)', { name: 'book' }, async (request) => request.params);
    catalog.get('/books/', { name: 'books' }, async () => []);
  },
  { prefix: '/catalog' }
);
await app.ready();

console.log(app.reverse('book', { id: 7 }));
console.log(app.reverse('books', null, { query: { page: 2 } }));
console.log(app.routeNames().book);
/catalog/book/7
/catalog/books/?page=2
{ url: '/catalog/book/:id(^\\d+$)', methods: [ 'GET', 'HEAD' ] }

As Django's path converters, a parameter can say its kind: /books/<int:pk>/ takes digits only and gives request.params.pk as a number (to the hooks of the route too); <slug:name> letters, digits, - and _; <uuid:id> a uuid; <str:name> (or <name>) any text but a slash; and <path:file> the rest of the address, slashes too (the last part of a route). A value that is not of its kind is not the route: 404.

A name is of one path (the same path by other methods is one name; another path is an error when the route is added); an unknown name, a parameter missing or not of its expression throw XUFA_ERR_ROUTE_NAME. xufa routes lists the named routes too.

The request

app.post('/books/:id/reviews', async (request) => {
  request.params; // { id: '42' }
  request.query; // the query string, parsed when it is first read: { sort: 'date' }
  request.body; // the body, parsed by its content type
  request.headers; // { 'content-type': 'application/json', ... }
  request.method; // 'POST'
  request.url; // '/books/42/reviews?sort=date'
  request.ip; // the address of the client (or of X-Forwarded-For with trustProxy)
  request.hostname; // 'api.example.com'
  request.protocol; // 'https' (with trustProxy, from X-Forwarded-Proto)
  request.id; // the id of the request, in its logs
  request.log; // the logger of the request
  request.signal; // an AbortSignal, aborted when the client goes away or handlerTimeout passes
  request.routeOptions; // { url: '/books/:id/reviews', method, config, bodyLimit, ... }
  request.server; // the app (the instance of the plugin of the route)
  request.raw; // Node's IncomingMessage
});

request.signal is the way to stop work nobody waits for: give it to fetch, to a query of the database, to @xufa/client (client.for(request) does it for you).

The reply

app.get('/report', async (request, reply) => {
  reply.code(202); // the status (200 by default)
  reply.header('cache-control', 'no-store'); // a header (headers({...}) for several)
  reply.type('text/csv'); // the content type
  return 'id,title\n1,Dune\n';
});

app.get('/old', async (request, reply) => reply.redirect('/new', 301));

app.get('/file', async (request, reply) => {
  reply.type('application/pdf');
  return fs.createReadStream('report.pdf'); // a stream is piped
});

const report = await app.inject('/report');
console.log(report.statusCode, report.headers['content-type'], report.headers['cache-control']);
const old = await app.inject('/old');
console.log(old.statusCode, old.headers.location);
202 text/csv no-store
301 /new

Returning or sending

An async handler returns its reply. reply.send() sends one too: use it in handlers that are not async, or from a callback. In an async handler that calls reply.send(), return the reply (return reply.send(...)) so that xufa knows it was sent. 

app.get('/a', async () => ({ a: 1 })); // returned

app.get('/b', (request, reply) => {
  reply.send({ b: 1 }); // sent, by a handler that is not async
});

app.get('/c', async (request, reply) => {
  setTimeout(() => reply.send({ c: 1 }), 10);
  return reply; // sent later: return the reply, not undefined
});

for (const url of ['/a', '/b', '/c']) console.log(url, (await app.inject(url)).body);
/a {"a":1}
/b {"b":1}
/c {"c":1}

An async handler that returns undefined without sending answers 200 with an empty body. Return what the reply is, or the reply itself when it is sent later.

Validation

A route's schema describes its request with JSON Schema: body, querystring, params and headers. They are compiled by @xufa/schema when the app starts, and a request that does not fit gets a 400 before the handler runs. 

app.post(
  '/users',
  {
    schema: {
      body: {
        type: 'object',
        required: ['name'],
        properties: { name: { type: 'string', minLength: 1 }, age: { type: 'integer', default: 18 } },
        additionalProperties: false,
      },
    },
  },
  async (request, reply) => reply.code(201).send(request.body) // the body as the handler gets it
);

for (const payload of ['{"name":"Ada","extra":1}', '{"name":""}', '{}', '{bad']) {
  const response = await app.inject({
    method: 'POST',
    url: '/users',
    headers: { 'content-type': 'application/json' },
    payload,
  });
  console.log(payload, '->', response.statusCode, response.json().message ?? response.body);
}
{"name":"Ada","extra":1} -> 201 {"name":"Ada","age":18}
{"name":""} -> 400 body/name must NOT have fewer than 1 characters
{} -> 400 body must have required property 'name'
{bad -> 400 Body is not valid JSON but content-type is set to 'application/json'

The handler gets { name: 'Ada', age: 18 }: extra removed, age by its default.

As fastify configures ajv, the validator converts types (coerceTypes: 'array': the text '42' of a parameter becomes 42 for an integer, a single query value becomes an array for an array), applies defaults (useDefaults) and removes the properties a schema with additionalProperties: false does not have (removeAdditional). With a schema of params such as { id: { type: 'integer' } }, request.params.id is a number, and /items/x is a 400 (params/id must be integer).

The options of the validator are those of ajv that it shares, in ajv.customOptions:

const app = xufa({
  ajv: { customOptions: { coerceTypes: false, allErrors: true, formats: { slug: /^[a-z0-9-]+$/ } } },
  validation: { foldMessages: true }, // options of @xufa/schema itself
});

Schemas written with s

s of @xufa/schema writes the same JSON Schema with less to type, and derives schemas from schemas: the body of a create without the id, a patch with every property optional. 

import { s } from '@xufa/schema';

const Book = s.object(
  { id: s.integer(), title: s.string({ minLength: 1 }), tags: s.array(s.string()), pages: s.optional(s.integer()) },
  { additionalProperties: false }
);
const NewBook = s.omit(Book, ['id']);
const BookPatch = s.partial(NewBook);
const BookId = s.object({ id: s.integer() });

app.post('/books', { schema: { body: NewBook, response: { 201: Book } } }, createBook);
app.patch('/books/:id', { schema: { params: BookId, body: BookPatch, response: { 200: Book } } }, updateBook);

const created = await app.inject({ method: 'POST', url: '/books', payload: { title: 'Dune', tags: ['sf'] } });
const patched = await app.inject({ method: 'PATCH', url: '/books/1', payload: { pages: 412 } });
const refused = await app.inject({ method: 'PATCH', url: '/books/1', payload: { title: '' } });
console.log(created.statusCode, created.body);
console.log(patched.statusCode, patched.body);
console.log(refused.statusCode, refused.json().message);
201 {"id":1,"title":"Dune","tags":["sf"]}
200 {"id":1,"title":"Dune","tags":["sf"],"pages":412}
400 body/title must NOT have fewer than 1 characters

In TypeScript, they type the request too (TypeScript).

Shared schemas

app.addSchema() adds a schema with an $id that routes refer to with $ref. Like everything an app adds, it is seen by the plugins registered in it after. 

app.addSchema({
  $id: 'Book',
  type: 'object',
  properties: { id: { type: 'integer' }, title: { type: 'string' } },
});

app.get('/books', { schema: { response: { 200: { type: 'array', items: { $ref: 'Book#' } } } } }, listBooks);
app.get('/books/:id', { schema: { response: { 200: { $ref: 'Book#' } } } }, getBook);

console.log((await app.inject('/books')).body); // listBooks gives a secret too: not in Book, not sent
[{"id":1,"title":"Dune"}]

Serialization

A response schema, by status (200, 201, '2xx', default), compiles a serializer with @xufa/serializer: replies are written faster than by JSON.stringify, and only with the properties of the schema. A field nobody should see (a hash of a password) cannot leak through a route whose response schema does not have it. 

app.get(
  '/me',
  { schema: { response: { 200: s.object({ id: s.integer(), name: s.string() }) } } },
  async (request) => db.users.get(request.user.id) // { id, name, passwordHash }: passwordHash is not sent
);

console.log((await app.inject('/me')).body);
{"id":7,"name":"Ada"}

Different from fastify: large replies (arrays, maps, recursive schemas) are written as UTF-8 bytes, without making a string first: about 1.4× fastify on a big JSON reply. onSend hooks still get a string.

When a request is not valid

The 400 of an invalid request has its first error as message:

{"statusCode":400,"code":"XUFA_ERR_VALIDATION","error":"Bad Request","message":"body/name must NOT have fewer than 1 characters"}

The error has validation (the list of errors, as ajv makes them: instancePath, keyword, params, message) and validationContext ('body', 'querystring'...), for an error handler that answers in a format of its own: 

app.setErrorHandler((error, request, reply) => {
  if (error.validation) {
    return reply.code(422).send({
      errors: error.validation.map((e) => ({ field: e.instancePath.slice(1) || null, problem: e.message })),
    });
  }
  return reply.send(error);
});

const response = await app.inject({ method: 'POST', url: '/users', payload: { age: -1 } });
console.log(response.statusCode, response.body);
422 {"errors":[{"field":null,"problem":"must have required property 'name'"},{"field":"age","problem":"must be >= 0"}]}

(With allErrors: true in ajv.customOptions; without it, the first error only.)

schemaErrorFormatter changes the message only; attachValidation: true lets the handler decide (request.validationError); ajv: { customOptions: { allErrors: true } } reports every error instead of the first.

Plugins

A plugin is a function that adds to an app: routes, hooks, decorators, schemas, other plugins. app.register(plugin, options) loads it, in order: plugins registered first are loaded first, and an async plugin is waited for before the next. 

// A plugin: a function of (app, options).
async function books(app, options) {
  app.get('/', async () => listBooks({ limit: options.limit }));
}

app.register(books, { prefix: '/books', limit: 50 }); // its routes under /books

await app.ready(); // every plugin loaded (listen() and inject() wait for it too)
console.log((await app.inject('/books')).body);
{"limit":50}

prefix is for the paths of its routes; the other options are the plugin's own. Plugins of fastify's ecosystem register the same way (see which ones).

Encapsulation

A plugin gets an app of its own, a child of the app it is registered in: what it adds (decorators, hooks, schemas, an error handler, content type parsers) stays in it and in its children. The parent sees none of it. This is how a part of an app has its own hooks (authentication for /admin only) without the rest paying for them. 

app.register(
  async (admin) => {
    admin.addHook('onRequest', requireAdmin); // only the routes of this plugin
    admin.get('/stats', getStats);
  },
  { prefix: '/admin' }
);

app.get('/public', getPublic); // no requireAdmin here

for (const url of ['/admin/stats', '/public']) {
  const response = await app.inject(url);
  console.log(url, response.statusCode, response.body);
}
/admin/stats 403 {"message":"Admins only"}
/public 200 {"hello":"world"}

To add to the app that registers it (a database connection every route uses), wrap the plugin in xufa.plugin() (fastify-plugin): it then adds to its parent. 

import { plugin } from '@xufa/http';

export default plugin(
  async (app, options) => {
    const db = await connect(options.url);
    app.decorate('db', db);
    app.addHook('onClose', () => db.close());
  },
  { name: 'db', xufa: '0.x' } // its name (for dependencies), and the versions of xufa it needs
);

Decorators

decorate adds a property to the app, decorateRequest to every request and decorateReply to every reply. Declare them once, at the start, so that every request and reply has the same shape (which V8 makes fast); then set their values in hooks. 

app.decorate('config', { name: 'books' }); // app.config
app.decorateRequest('user', null); // request.user, null until a hook sets it

app.addHook('onRequest', async (request) => {
  request.user = await userOf(request.headers.authorization);
});

app.get('/me', async (request) => ({ app: app.config.name, user: request.user }));
console.log((await app.inject({ url: '/me', headers: { authorization: 'Bearer ada' } })).body);
console.log((await app.inject('/me')).body);
{"app":"books","user":{"id":"ada"}}
{"app":"books","user":null}

A request decorator cannot be an object or an array (XUFA_ERR_DEC_REFERENCE_TYPE): it would be the same object for every request. Use null and set it in a hook, or a getter ({ getter() {...} }).

Hooks

Hooks run at each step of a request, in this order:

HookWhenUsed for
onRequestThe request has come, its body not readAuthentication, rate limits: refusing early is cheapest
preParsingBefore the body is parsedChanging the stream of the body (decompressing it)
preValidationThe body parsed, before validationChanging the body before it is checked
preHandlerValidated, before the handlerLoading what the handler needs; permissions that need the body
preSerializationThe handler returned an object, before it is serializedWrapping replies ({ data: ... })
onSendSerialized, before sendingHeaders, compressing, changing the bytes
onResponseSentMetrics
onErrorAn error, before it is sentReporting errors (it cannot change the reply)
onTimeout, onRequestAbortThe socket timed out; the client went awayCleaning up
 
app.addHook('onRequest', async (request, reply) => {
  if (!request.headers.authorization) return reply.code(401).send({ message: 'Log in first' }); // stops here
});

app.addHook('onSend', async (request, reply, payload) => {
  reply.header('x-served-by', 'books');
  return payload; // onSend and preSerialization return the payload, changed or not
});

app.get('/slow', { onRequest: [rateLimit], preHandler: [loadBook] }, handler); // hooks of one route

const refused = await app.inject('/slow');
const served = await app.inject({ url: '/slow', headers: { authorization: 'Bearer ada' } });
console.log(refused.statusCode, refused.body);
console.log(served.statusCode, served.headers['x-served-by'], served.body);
401 {"message":"Log in first"}
200 books {"title":"Dune"}

Hooks are async functions, or functions with a done callback as their last argument (not both: XUFA_ERR_HOOK_INVALID_ASYNC_HANDLER). A hook that sends a reply ends the request there.

The app has hooks of its own: onRoute (each route added), onRegister (each plugin), onReady, onListen, preClose and onClose.

Errors

Throw an error from a handler or a hook (or return it, or reply.send(error)): its statusCode is the status of the reply, 500 without one. @xufa/errors makes classes of errors with a code, a status and a message: 

import createError from '@xufa/errors';

const BookGone = createError('APP_BOOK_GONE', 'Book %s is gone', 410);

app.get('/books/:id', async (request) => {
  const book = await findBook(request.params.id);
  if (book.deletedAt) throw new BookGone(book.title);
  return book;
});

const response = await app.inject('/books/1');
console.log(response.statusCode, response.body);
410 {"statusCode":410,"code":"APP_BOOK_GONE","error":"Gone","message":"Book Dune is gone"}

By default, the message of an error is sent, 500s included, as fastify does: a thrown new Error('connect ECONNREFUSED 10.0.0.5:5432') tells the client where the database is. Set an error handler that hides the messages of 500s (below).

Error handlers

app.setErrorHandler(async (error, request, reply) => {
  const status = error.statusCode >= 400 ? error.statusCode : 500;
  if (status >= 500) request.log.error(error); // logged with the request's id
  reply.code(status);
  return { error: status >= 500 ? 'Something failed' : error.message, code: error.code };
});

app.get('/db', async () => {
  throw new Error('connect ECONNREFUSED 10.0.0.5:5432');
});
app.get('/teapot', async () => {
  throw Object.assign(new Error('No coffee here'), { statusCode: 418, code: 'APP_TEAPOT' });
});

for (const url of ['/db', '/teapot']) {
  const response = await app.inject(url);
  console.log(url, response.statusCode, response.body);
}
/db 500 {"error":"Something failed"}
/teapot 418 {"error":"No coffee here","code":"APP_TEAPOT"}

An error handler is encapsulated like the rest: a plugin can have its own (its errors, and those of its children). Errors it throws go to the error handler of the parent.

One context has one handler of setErrorHandler. app.addErrorHandler(fn) adds one over those of the context without taking it: plugins add theirs (the ORM's answers its validation errors as 400 and duplicates as 409; errorPages the pages of browsers), the last added goes first, and the app may still set its own, which goes before them. A handler that throws the error (or sends it) passes it to the one under it.

Not found

app.setNotFoundHandler(async (request, reply) => {
  reply.code(404);
  return { error: `No ${request.method} ${request.url}` };
});

const response = await app.inject('/nope');
console.log(response.statusCode, response.body);
404 {"error":"No GET /nope"}

Without one, an unknown route answers {"message":"Route GET:/nope not found","error":"Not Found","statusCode":404}. Plugins with a prefix can have their own; reply.callNotFound() sends a request to it from a handler.

Error pages

xufa.errorPages is Django's handler404, handler403, handler400 and handler500 with their templates: a request of a browser (Accept: text/html) that fails gets the view of @xufa/template of its status, with that status; the others (API clients) go on to the error handlers under it, as JSON. Statuses without a view go on too, and a view that fails passes the error on as it was. 

app.register(template.plugin, { root: 'templates' });
app.register(xufa.errorPages, { views: { 404: '404', 403: '403', 500: '500' } }); // or views: 'errors' (errors/404...)

A view gets statusCode, title (Not Found), message (that of the error for 4xx; for 5xx that of the status: their messages are for the logs, where they go), permission (of a 403 of permissionRequired), error (4xx), and what context(error, request) adds. 5xx without a view of their own take that of 500. With notFound (true), routes that are not there are 404s of it too (it sets the not-found handler). In development, devErrors shows its page over them.

The page of errors in development

xufa.devErrors gives browsers a page when a request fails, as Laravel's Ignition and Django's debug page: the error and its causes, the stack with the lines of the source around each call of the app, the request (params, query, body, headers; those of credentials hidden) and the routes. A route that is not there shows the list of the routes. Requests that do not ask for HTML get the JSON they get without it. 

app.register(xufa.devErrors); // off when NODE_ENV is production
app.get('/books/:id', async () => {
  throw new Error('The database is down');
});

const page = await app.inject({ url: '/books/7', headers: { accept: 'text/html' } });
console.log(page.statusCode, page.headers['content-type']);
const json = await app.inject('/books/7');
console.log(json.statusCode, json.json().message);
500 text/html; charset=utf-8
500 The database is down

It is on unless NODE_ENV is production (enabled: true turns it on anyway: never where others can reach the app, since it shows the code). context is the lines around each call (5); notFound: false leaves the 404 pages to the app. It sets no handlers: the error handlers of the app and of its plugins answer as they do, and for a browser what they send is replaced by the page, with their status.

Health

xufa.health gives the routes load balancers, Kubernetes and people ask: GET /health/live (the process answers), GET /health/ready (the app can serve: 503 when a critical check is down, or while it closes) and GET /health (every check, with its status, time, error and details). A check is a function: what it gives is up (its details), false or a text is down, what throws or goes over its timeout (2 s) is down, and { status: 'degraded', ...details } is degraded. 

let nodes = 3;
app.register(xufa.health, {
  checks: {
    database: () => 1.2, // db.ping() of @xufa/orm: the ms of a round trip, or it throws
    converters: () => nodes > 0 || 'no converters',
    queue: { check: () => ({ status: 'degraded', failed: 4 }), critical: false },
  },
  cache: 0,
});

const report = (await app.inject('/health')).json();
console.log(report.status, report.checks.database.status, report.checks.queue.details);
nodes = 0;
const ready = await app.inject('/health/ready');
console.log(ready.statusCode, ready.json(), (await app.inject('/health')).json().checks.converters.error);
degraded up { failed: 4 }
503 { status: 'down' } no converters
  • The status of the app: down when a critical check is (every check is critical but those with critical: false), degraded when another is down or one is degraded (still 200), up otherwise.
  • interval: '10s' runs the checks in the background, as a status checker: the routes answer from the last run. Without it they run when asked, at most every cache (1 s).
  • onChange(status, previous, report) tells when the status changes (an alert, a message to a channel); it is logged too.
  • heal: { after: '5m', run(result) } in a check runs a cure when it has been down that long (restart what it checks), and again after another after while it stays down.
  • The packages of xufa give their checks, ready for checks: db.health({ slow }) of @xufa/orm (critical: the latency of a ping), queue.health({ maxLag, maxPending, maxFailed }) of @xufa/queue, pool.health({ minNodes, maxWaiting }) of @xufa/cluster and netcache.health({ minPeers }) of @xufa/netcache (not critical: the app serves without them, degraded). Each takes critical and timeout: checks: { database: db.health(), queue: queue.health({ maxLag: '5m' }), converters: usePool('converters').health(), cache: netcache.health() }.
  • prefix ('/health'), details: false (the status only, for routes others can reach), logLevel of the routes ('warn': probes do not fill the logs). app.health.check() runs them now; app.health.report and app.health.status tell the last run (typed in the app of TypeScript, as app.maintenance).

Maintenance mode

As Laravel's php artisan down: while it is on, every request gets a 503 with Retry-After, a page for browsers and JSON for the rest, but the health routes, the routes with config: { maintenance: false } (webhooks), the addresses allowed and the browsers that opened its secret path. xufa down turns it on and xufa up off (see the command line). 

let state = null; // what xufa down writes: a file, or maintenance(db) of @xufa/orm
app.register(xufa.maintenance, { file: false, store: { get: () => state }, refresh: 0 });
app.get('/books', async () => ['Dune']);

console.log(down.statusCode, down.headers['retry-after'], down.json().message);
const cookie = (await app.inject('/let-me-in')).headers['set-cookie'].split(';')[0];
console.log((await app.inject({ url: '/books', headers: { cookie } })).statusCode);

  • Where it is kept: file (.xufa/down.json of the folder of the app: this machine) and store (one or several objects with get(); maintenance(db) of @xufa/orm keeps it in the database, for every machine). It is read at most every refresh (1 s); a store that fails counts as up.
  • The state: message, retryAfter (seconds), allow (addresses), secret (opening /<secret> gives a cookie that goes through, for 12 hours) and redirect (where it goes then).
  • except (['/health', '/health/*']) and render(state, request) (the page). app.maintenance.state() reads it now.

Bodies and content types

JSON (application/json, and types ending in +json) and text (text/plain) are parsed. Bodies with __proto__ or constructor.prototype are refused (onProtoPoisoning, onConstructorPoisoning), and bodies larger than bodyLimit (1 MiB) are a 413. Other types are a 415 unless you add a parser: 

app.addContentTypeParser('text/csv', { parseAs: 'string' }, (request, body, done) => {
  done(null, body.split('\n').map((line) => line.split(',')));
});
app.post('/import', async (request) => ({ rows: request.body.length, first: request.body[1] }));

// The body as it comes, a stream: for uploads.
app.addContentTypeParser('application/octet-stream', (request, payload, done) => done(null, payload));
app.put('/files/:name', async (request) => {
  await pipeline(request.body, fs.createWriteStream(path.join(dir, request.params.name)));
  return { saved: request.params.name };
});

const csv = await app.inject({
  method: 'POST',
  url: '/import',
  headers: { 'content-type': 'text/csv' },
  payload: 'id,title\n1,Dune',
});
const upload = await app.inject({
  method: 'PUT',
  url: '/files/notes.txt',
  headers: { 'content-type': 'application/octet-stream' },
  payload: 'some bytes',
});
const xml = await app.inject({ method: 'POST', url: '/import', headers: { 'content-type': 'application/xml' }, payload: '<a/>' });
console.log(csv.body);
console.log(upload.body, fs.readFileSync(path.join(dir, 'notes.txt'), 'utf8'));
console.log(xml.statusCode, xml.json().code);

Forms

xufa.formBody parses the bodies of HTML forms, as Django's request.POST and request.FILES: application/x-www-form-urlencoded and multipart/form-data become request.body. A field given again, or named with [], is a list; a file is { filename, contentType, size, data } (data, a Buffer). 

app.register(xufa.formBody, { fileSize: 5 * 1024 * 1024 });
app.post('/books', async (request) => {
  const { title, genre, cover } = request.body;
  return { title, genre, cover: cover && [cover.filename, cover.size] };
});

const form = await app.inject({
  method: 'POST',
  url: '/books',
  headers: { 'content-type': 'application/x-www-form-urlencoded' },
  payload: 'title=Dune&genre=1&genre=3',
});
const boundary = 'xufa';
const upload = await app.inject({
  method: 'POST',
  url: '/books',
  headers: { 'content-type': `multipart/form-data; boundary=${boundary}` },
  payload: [
    `--${boundary}`,
    'Content-Disposition: form-data; name="title"', '', 'Dune',
    `--${boundary}`,
    'Content-Disposition: form-data; name="cover"; filename="cover.png"', 'Content-Type: image/png', '', 'PNG...',
    `--${boundary}--`, '',
  ].join('\r\n'),
});
console.log(form.body);
console.log(upload.body);
{"title":"Dune","genre":["1","3"]}
{"title":"Dune","cover":["cover.png",6]}

Limits: bodyLimit (1 MiB for urlencoded bodies, 20 MiB for multipart ones), files (10), fileSize (10 MiB), fields (1000), fieldSize (1 MiB) and parts (1000); past one, the answer is 413 (too large) or 400. multipart: false parses urlencoded bodies only. Keys of prototypes (__proto__) are dropped.

Static files

xufa.staticFiles serves the files of some folders under a prefix, as Django's staticfiles with whitenoise: their type, an ETag and Last-Modified (304 when the browser has the file), and the .br or .gz file next to one when the browser takes it. app.staticUrl(path) is the address of a file with its version (a hash of its bytes), as {% static %}: an address with the right version is cached for a year, so a page links to the file it was written for and a new deploy changes the address. 

app.register(xufa.staticFiles, { root: [dir], prefix: '/static/' });
await app.ready();

const address = app.staticUrl('css/site.css'); // in the templates: <link href="{{ staticUrl('css/site.css') }}">
const res = await app.inject(address);
const again = await app.inject({ url: address, headers: { 'if-none-match': res.headers.etag } });
console.log(address.replace(/v=\w+/, 'v=...'));
console.log(res.statusCode, res.headers['content-type'], res.headers['cache-control']);
console.log(again.statusCode, (await app.inject('/static/../secret')).statusCode);
/static/css/site.css?v=...
200 text/css; charset=utf-8 public, max-age=31536000, immutable
304 404

root is a folder or a list (the first with the file serves it); paths out of them, names that start with a dot and folders are a 404. maxAge is the cache of addresses without their version (0: the browser asks again, with the ETag), immutable that of versioned ones; types adds types by extension.

Logs

logger: true (or the options of a logger) makes an @xufa/logger: pino's options and API, without transports. Each request has its logger, request.log, whose lines carry the request's id. 

const app = xufa({
  logger: {
    level: process.env.LOG_LEVEL || 'info',
    redact: ['req.headers.authorization', 'req.headers.cookie'],
  },
  disableRequestLogging: (request) => request.url === '/health', // no lines for health checks
  requestIdHeader: 'x-request-id', // the id given by a proxy, when there is one
});

app.get('/books', async (request) => {
  request.log.info({ filter: request.query }, 'listing books');
  return listBooks(request.query);
});

Lines are JSON, for the tools that collect logs; to read them in development, pipe them through pino-pretty. A logger of your own (pino with transports) goes in loggerInstance.

Testing

app.inject() sends a request to the app without a socket (@xufa/inject): fast, and nothing listens. With the app made by a function (The layout of an app), each test has an app of its own. 

import { build } from '../app.js';

describe('books', () => {
  let app;
  beforeEach(() => {
    app = build();
  });
  afterEach(() => app.close());

  it('creates a book', async () => {
    const response = await app.inject({ method: 'POST', url: '/books', payload: { title: 'Dune' } });
    expect(response.statusCode).toBe(201);
    expect(response.json()).toMatchObject({ title: 'Dune' });
  });

  it('refuses a book without a title', async () => {
    const response = await app.inject({ method: 'POST', url: '/books', payload: {} });
    expect(response.statusCode).toBe(400);
  });
});

app.inject() also chains: app.inject().post('/books').headers({...}).payload({...}).end(). For failures of what the app depends on (a slow database, an API that answers 503), see @xufa/faults.

The client of tests

new xufa.TestClient(app) is Django's test Client: a browser over inject() that keeps its cookies (its session), posts forms (post(url, data); JSON with { json: true }) with the CSRF token of its session (enforceCsrfChecks: true sends none), follows redirects ({ follow: true }: res.redirectChain), and logs in: login(credentials) (whether they log in, with the accounts of @xufa/auth) and forceLogin(user) (without a password). Each response says which views of @xufa/template it rendered and with what: res.templates (assertTemplateUsed), res.context (Django's response.context), and res.textContent (the text a reader sees). 

const client = new xufa.TestClient(app);
await client.forceLogin(librarian);
const res = await client.get('/catalog/authors/', { page: 2 });
expect(res.templates).toEqual(['catalog/author_list']);
expect(res.context.isPaginated).toBe(true);
expect(res.context.authorList).toHaveLength(3);

const made = await client.post('/catalog/author/create/', { firstName: 'Ada', lastName: 'Lovelace' }, { follow: true });
expect(made.textContent).toContain('Author: Lovelace, Ada');

TypeScript

The declarations are fastify's, with xufa's names: XufaInstance, XufaRequest, XufaReply, XufaPluginAsync, XufaPluginCallback, XufaSchema... Routes are typed by generics, or by a type provider that reads their schemas: 

import xufa, { type XufaPluginAsync } from '@xufa/http';
import { s, type SchemaTypeProvider } from '@xufa/schema';

const NewBook = s.object({ title: s.string({ minLength: 1 }), pages: s.optional(s.integer()) });

const books: XufaPluginAsync = async (app) => {
  const typed = app.withTypeProvider<SchemaTypeProvider>();
  typed.post('/', { schema: { body: NewBook } }, async (request) => {
    request.body.title; // string
    request.body.pages; // number | undefined
    return { ok: true };
  });

  // Or by generics, without schemas:
  app.get<{ Params: { id: string }; Querystring: { full?: boolean } }>('/:id', async (request) => {
    return getBook(request.params.id, request.query.full);
  });
};

const app = xufa();
app.register(books, { prefix: '/books' });

Decorators are typed by declaring them on the interfaces of xufa: 

declare module '@xufa/http' {
  interface XufaInstance {
    db: Database;
  }
  interface XufaRequest {
    user: { id: string; role: string } | null;
  }
}

In production

  • Listen on every interface in a container (host: '0.0.0.0'), on the port the platform gives (process.env.PORT).
  • Behind a proxy (a load balancer, nginx), set trustProxy (true, the number of proxies, or their addresses) so that request.ip, hostname and protocol are the client's.
  • Close gracefully: on SIGTERM, app.close() stops accepting connections, lets the requests in flight end, and runs the onClose hooks (where databases are closed). New requests while it closes get a 503.
  • Timeouts: handlerTimeout (for the app or a route) answers 503 when a handler takes too long and aborts request.signal; requestTimeout and connectionTimeout protect from slow clients; keepAliveTimeout should be longer than the idle timeout of the load balancer in front.
  • Hide the messages of 500s with an error handler (Error handlers).
  • Use every CPU with @xufa/cluster: a process for each one, restarted when it dies. 
const app = build({ logger: true, trustProxy: 1, handlerTimeout: 10000 });

for (const signal of ['SIGINT', 'SIGTERM']) {
  process.once(signal, async () => {
    app.log.info({ signal }, 'closing');
    await app.close();
    process.exit(0);
  });
}

await app.listen({ port: Number(process.env.PORT) || 3000, host: '0.0.0.0' });

With the rest of xufa

The other packages of xufa are plugins of the app. An app with a database, users and its OpenAPI document:

import xufa from 'xufa';
import { Database, Model, fields, plugin as orm, resource } from 'xufa/orm';
import * as auth from 'xufa/auth';
import openapi from 'xufa/openapi';
import openapiUi from 'xufa/openapi/ui';
import { loadConfig } from 'xufa/config';
import schema from './config-schema.js';

const config = loadConfig({ schema });

class Book extends Model {
  static fields = { title: fields.string(), pages: fields.integer({ null: true }) };
}

const db = new Database(config.database); // { backend: 'postgres', url } or { backend: 'sqlite', filename }
db.register(Book, User, RefreshToken);

const app = xufa({ logger: config.logger });
await app.register(openapi, { openapi: { info: { title: 'Books', version: '1.0.0' } } });
await app.register(openapiUi, { routePrefix: '/docs' });
app.register(orm, { database: db, migrate: { dir: 'migrations' } });
app.register(auth.plugin, { keys: config.jwtKey, login: { findUser, claims } });

// GET, POST /books, GET, PATCH, DELETE /books/:id: validated by the fields of Book, in the OpenAPI document.
app.register(resource(Book, { auth: { create: ['editor'], update: ['editor'], delete: ['admin'] } }), {
  prefix: '/books',
});

app.get('/me', { config: { auth: true } }, async (request) => request.user);

await app.listen({ port: config.port, host: '0.0.0.0' });
  • @xufa/orm: models, migrations, resources, and the database of each tenant.
  • @xufa/auth: logging in, tokens, roles on routes.
  • @xufa/openapi: the document of the routes, its explorer, routes from a document.
  • @xufa/websocket: app.get('/chat', { websocket: true }, (socket) => ...).
  • @xufa/client: calls to other APIs, cancelled with the request (client.for(request)).
  • @xufa/scheduler: jobs every interval or by cron, as a plugin.
  • @xufa/cluster, @xufa/config: running it.
