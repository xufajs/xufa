@xufa/bundle

ES modules, JSX, TypeScript and the CommonJS packages they import, as one script for browsers, with their stylesheets. Syntax goes through TypeScript's transpiler, the one dependency (a peer: your project's); resolution, tree shaking, minifying and the registry of modules are its own. The page of @xufa/admin, with React and React Flow, is built with it, and so are the scripts of these docs' playgrounds.

Quick start

npm install --save-dev @xufa/bundle typescript
import fs from 'node:fs';
import { bundle } from '@xufa/bundle';

const { js, css } = bundle('client/src/main.jsx', {
  jsx: 'automatic',
  define: { 'process.env.NODE_ENV': '"production"' },
  minify: true,
});
fs.writeFileSync('dist/app.js', js);
fs.writeFileSync('dist/app.css', css);

bundle() is synchronous and gives { js, css, inputs, legal }: the script, the stylesheet, the files in them, and their legal comments.

Resolution

Relative files with their extensions (.js, .jsx, .mjs, .cjs, .ts, .tsx, .json, .css), index files, and ./a.js written for ./a.ts. Packages by exports (patterns too) with the conditions browser, import or require (as the module asks) and module; without exports, by the fields browser, module and main. A package's browser map replaces its files and modules, and false makes one empty. resolve(request, from) gives where an import goes.

define

// node_modules/react/index.js, with define: { 'process.env.NODE_ENV': '"production"' }
if (process.env.NODE_ENV === 'production') {
  module.exports = require('./cjs/react.production.js'); // the one bundled
} else {
  module.exports = require('./cjs/react.development.js'); // left out, and what it requires
}

The values of define are put in, and the branches they decide are left out: if, ?:, && and || whose conditions compare literals. import.meta is an empty object, as esbuild makes it in CommonJS.

Tree shaking

The top-level statements of an ES module that nothing needs are left out: declarations of functions, classes and values made without running code (literals, functions, objects and arrays of them, /* @__PURE__ */ calls) that no kept statement uses and no importer imports. Statements with side effects always stay. Modules nothing uses are not bundled when their package says "sideEffects": false (or does not list them), or when they only declare. What modules use of each other grows until it stops changing, through export ... from and export *. treeShaking: false keeps it all.

Stylesheets

import './styles.css' adds the stylesheet (with what it @imports, each once) to css, in the order the modules run: a package's styles before yours when it is imported first.

Minifying

The code is parsed again and written token by token: comments and white space out, a space only where two tokens would join, and a semicolon wherever a statement relied on a line break, so nothing depends on automatic semicolon insertion. true and false become !0 and !1, and trailing commas go. Local names are made short by their scopes: a name no outer name used inside the scope has, nor any global; nothing is renamed where a direct eval or with could reach it. /*! ... */ and @license comments are kept at the end.

The admin's page (React 19, React Flow and the admin) is 677 KB, 165 KB with brotli; esbuild makes it 603 KB and 159 KB. Every file of xufa's packages minifies to code V8 parses, and the suites of @xufa/expression, @xufa/yaml, @xufa/router and @xufa/marshal pass on their minified code.

Modules of Node.js

bundle('src/main.js', {
  shims: { 'node:util': "module.exports = { inspect: (value) => JSON.stringify(value) };" },
});

A module of Node.js without a shim is an error that says which one, and from where.

transform()

import { transform } from '@xufa/bundle';

const { code, imports, requires, legal } = transform(source, { file: 'view.tsx' });

One module as CommonJS: ES modules, JSX and TypeScript; CommonJS stays as written (not made strict). A module's own require, module or exports at its top level is renamed, so it does not clash with those of CommonJS. A syntax error says the file, line and column.

Coming from esbuild

esbuild.build({ entryPoints, bundle: true, format: 'iife', jsx: 'automatic', define, minify }) becomes bundle(entry, { jsx: 'automatic', define, minify: true }), and esbuild.transformSync(code, { format: 'cjs' }) becomes transform(code). Not there: code splitting and ES module output, source maps, watch and serve, plugins, CSS modules, and syntax lowering below ES2020. It is slower (about 2 seconds for the admin, where esbuild takes a fraction of one).

How it works

Every module reachable from the entry is read and made CommonJS by ts.transpileModule, with a transformer that puts in define and folds the branches it decides, and another that collects what each module requires. ES modules are parsed once more for tree shaking: what each top-level statement declares and uses (from the scopes of the module) and whether it is pure. The modules that stay are functions in a list, required by number on first use, with TypeScript's helpers once for all.
