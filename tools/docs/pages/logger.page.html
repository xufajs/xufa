@xufa/logger

A fast JSON logger with the API, the options and the output of pino, and no dependencies: one JSON object a line, made by functions compiled for each logger. It is the logger of @xufa/http (logger: true), and works on its own.

Quick start

npm install @xufa/logger
const logger = require('@xufa/logger')({ level: 'debug', redact: ['req.headers.authorization'] });

logger.info('hello %s', 'world');
logger.child({ requestId: 'r1' }).warn({ user: 7 }, 'slow request');
logger.error(new Error('failed')); // the error serialized as "err", its message as "msg"
{"level":30,"time":1759651200000,"pid":4120,"hostname":"web-1","msg":"hello world"}
{"level":40,"time":1759651200001,"pid":4120,"hostname":"web-1","requestId":"r1","user":7,"msg":"slow request"}
{"level":50,"time":1759651200002,"pid":4120,"hostname":"web-1","err":{"type":"Error","message":"failed","stack":"Error: failed\n    at ..."},"msg":"failed"}

Logging

trace, debug, info, warn, error and fatal, each as logger.info(object?, message?, ...args):

CallWrites
logger.info('user %s logged in after %d tries', name, tries)The message formatted (%s %d %i %f %j %o %O %%).
logger.info({ user, ms }, 'done')The properties of the object, and the message.
logger.error(err), logger.error(err, 'saving failed')The error under err (type, message, stack, cause...), and its message or the one given.
logger.info({ err }, 'retrying')Errors in objects are serialized too.

logger.level is the lowest level written (read and set it); isLevelEnabled(level) tells whether a level is written, to skip work that only a log needs. flush() writes what a buffered destination holds.

The output

One line of JSON for each log: level (a number: 10 trace, 20 debug, 30 info, 40 warn, 50 error, 60 fatal), time (milliseconds), the base bindings (pid, hostname, and name when given), the bindings of child loggers, the properties of the object, and msg. It is pino's output, so pino's tools read it: node app.js | pino-pretty.

Child loggers

const requestLog = logger.child({ requestId: req.id }, { level: 'debug', msgPrefix: '[api] ' });
requestLog.debug('parsing body'); // {"level":20,...,"requestId":"...","msg":"[api] parsing body"}
requestLog.bindings(); // { requestId: '...' }
requestLog.setBindings({ user: 7 });

A child logs with the bindings of its parent and its own; its options can change level, serializers, redact, msgPrefix and formatters. onChild(child) (an option) is called for every child made.

The formatters of a child are pino's: formatters.log replaces the one of its parent, for the child and its own children; formatters.bindings formats the bindings of the logger it is given to only (the base of the root logger; the bindings of a child, and those it gets with setBindings()), so a child has no bindings formatter but its own; formatters.level stays the parent's, as pino ignores it in a child.

A child without a level of its own follows the level of its parent, as in pino, changes included: after logger.level = 'debug', the children made before write their debug lines too. A child given a level ({ level } in its options, or child.level = ...) keeps it, whatever its parent does.

The second argument is the stream to write to (process.stdout by default): a stream, or a destination.

Levels

const logger = pino({ customLevels: { audit: 35 }, level: 'debug' });
logger.audit({ user: 7 }, 'password changed'); // {"level":35,...}
logger.levels; // { values: { trace: 10, ..., audit: 35, ... }, labels: { ... } }

useOnlyCustomLevels: true leaves only the custom ones.

Serializers

const logger = pino({
  serializers: {
    user: (user) => ({ id: user.id }), // only the id of a user goes to the logs
    req: pino.stdSerializers.req,
    res: pino.stdSerializers.res,
  },
});
logger.info({ user, req }, 'request');

A serializer runs on the property of its name. stdSerializers has err (errors, with their cause and own properties), req and res (of node:http), and their wrappers, as pino-std-serializers.

Redaction

pino({ redact: ['req.headers.authorization', 'user.password', 'cards[*].number'] });
pino({ redact: { paths: ['secret'], censor: '***' } });
pino({ redact: { paths: ['token'], remove: true } }); // the key is not written at all

Paths with dots, brackets (a["b-c"]) and wildcards (*); the default censor is [Redacted], and it can be a function of the value and the path.

Formatters, mixins and hooks

pino({
  formatters: {
    level: (label, number) => ({ level: label }), // "level":"info" instead of 30
    bindings: (bindings) => ({ host: bindings.hostname }),
    log: (object) => ({ ...object, env: 'prod' }),
  },
  mixin: () => ({ traceId: currentTraceId() }), // added to every line
  hooks: {
    logMethod(args, method) { return method.apply(this, args); }, // see or change the arguments of every log
    streamWrite: (line) => line, // the line before it is written
  },
});

Destinations

const pino = require('@xufa/logger');

const logger = pino(pino.destination({ dest: './app.log', sync: false, minLength: 4096, mkdir: true }));
process.on('SIGHUP', () => logger[pino.symbols.streamSym].reopen()); // log rotation
process.on('exit', () => logger.flush());

destination() writes to a file descriptor (1, stdout, by default) or a file, synchronously (the default) or buffered ({ sync: false, minLength }), as sonic-boom does for pino: reopen() after the file is rotated, flush(), end().

Several streams

const logger = pino(
  { level: 'debug' },
  pino.multistream([
    { stream: process.stdout, level: 'info' },
    { stream: pino.destination('./debug.log'), level: 'debug' },
    { stream: pino.destination('./errors.log'), level: 'error' },
  ])
);

Each line goes to the streams whose level is at most its own.

In xufa

xufa({ logger: true }), or logger options, makes an @xufa/logger; loggerInstance takes one you made (or a pino). Every request has request.log, a child with its id, and the framework logs requests, responses and errors as fastify does.

Coming from pino

  • The options, the methods and the output are pino's; require('pino') can be replaced by require('@xufa/logger').
  • Transports (transport, pino.transport()) are not there: it throws. Logs go to a stream: give one, or pipe the output of the process (node app.js | pino-pretty, or to your collector).
  • Not there either: the level-change event, levelComparison, depthLimit and edgeLimit, and pino's browser build.

TypeScript

const options: LoggerOptions = { level: 'info', redact: ['password'] };
