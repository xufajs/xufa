@xufa/session

Sessions of browsers for @xufa/http, as those of Django and Laravel: values kept between the requests of a browser by a signed cookie, in memory or in a database of @xufa/orm (any backend, deleted when they expire), with flash messages and CSRF tokens. No dependencies.

Quick start

const xufa = require('@xufa/http');
const { sessionPlugin } = require('@xufa/session');

const app = xufa();
app.register(sessionPlugin, { secret: 'a secret of 32 characters or more!!' }); // process.env.SESSION_SECRET

app.get('/visits', async (request) => {
  const visits = (request.session.get('visits') || 0) + 1;
  request.session.set('visits', visits);
  return { visits };
});

const first = await app.inject('/visits');
const cookie = first.headers['set-cookie'].split(';')[0]; // what a browser keeps
const second = await app.inject({ url: '/visits', headers: { cookie } });
console.log(first.json(), second.json());
{ visits: 1 } { visits: 2 }

Values

request.session has get(key), set(key, value), has, delete, all() and clear(). Values are JSON. A session is saved when the reply is sent, if it changed; a request that does not use it makes none (and no cookie).

Logins and logouts

app.post('/login', async (request, reply) => {
  const user = await checkPassword(request.body);
  request.session.regenerate().set('userId', user.pk);
  return reply.redirect('/');
});
app.post('/logout', async (request, reply) => {
  request.session.destroy();
  return reply.redirect('/');
});

regenerate() gives the session a new id and deletes the old one: an id someone learned before the login is worth nothing after it. destroy() ends the session and clears its cookie.

Flash messages

flash(key, value) keeps a value for the next request only, as Rails and Laravel do: a message set before a redirect, shown by the page after it. flash(key) reads it. 

request.session.flash('notice', 'Saved');   // then reply.redirect('/books')
const notice = request.session.flash('notice'); // in the next request; gone after it

CSRF

With csrf: true, POST, PUT, PATCH and DELETE of a session need its token: forms send csrfToken() back in a field _csrf, and scripts in the header x-csrf-token; a 403 otherwise. Requests without a session (they act as nobody) and routes with config: { csrf: false } (webhooks) need none. 

<form method="post" action="/books">
  <input type="hidden" name="_csrf" value="{{ csrf }}">
  ...
</form>

Stores

memoryStore() (the default) keeps sessions in the process: for tests and development. ormStore(db) keeps them as objects of a model of the ORM (table xufa_sessions) in any backend, for every process and machine with the database; its TTL index deletes those that expired (db.expire(), or the option expire of the plugin of the ORM). A store of your own has get(id), set(id, data, expiresAt) and delete(id).
