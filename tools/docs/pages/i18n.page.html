@xufa/i18n

The messages of an app in its languages: catalogs by locale, plurals by the rules of each language (Intl.PluralRules), parameters, and the locales a locale falls back to. The locale of each request is kept in its async context, so code far from the request speaks it too: the validation messages of @xufa/orm, translated into Spanish, French, German, Portuguese and Italian. No dependencies.

Quick start

import { I18n } from '@xufa/i18n';

const i18n = new I18n({
  fallback: 'en',
  locales: {
    en: { hello: 'Hello, {name}!', cart: { items: { zero: 'Your cart is empty', one: '{count} item', other: '{count} items' } } },
    es: { hello: '¡Hola, {name}!', cart: { items: { one: '{count} artículo', other: '{count} artículos' } } },
    'es-AR': { hello: '¡Hola, {name}! ¿Todo bien?' },
  },
});

console.log(i18n.t('hello', { name: 'Ada' }, 'es-AR'));
console.log(i18n.t('cart.items', { count: 0 }, 'en'), '|', i18n.t('cart.items', { count: 3 }, 'es-MX'));
i18n.run('es', () => console.log(i18n.t('cart.items', { count: 1 }), i18n.number(12345.5)));
¡Hola, Ada! ¿Todo bien?
Your cart is empty | 3 artículos
1 artículo 12.345,5

Catalogs

  • A catalog is an object of messages by key, nested ({ cart: { title } }) or with dots ({ 'cart.title': ... }); i18n.add(locale, catalog) adds more (from JSON files, say).
  • t(key, params, locale): {name} are the parameters. A locale looks in itself, then in its language, then in the fallback: es-AR, es, en. A key without a message gives the key (or missing(key, locale)).
  • number(), date() and list() format in the locale of the context, with the options of Intl.

Plurals

A message in the plural is an object of the forms of each language (zero, one, two, few, many, other): params.count chooses one by the rules of the language (Russian has one, few and many; English one and other), and zero, when the message has it, is for 0.

The locale of a request

app.register(i18nPlugin, { i18n, detect: ['query', 'cookie', 'user', 'header'] }); // import { plugin as i18nPlugin } from '@xufa/i18n'
app.get('/cart', (request) => ({ title: request.t('cart.title'), locale: request.locale }));
  • The locale of each request is the first of detect that matches a locale with a catalog: ?lang=es (query), the cookie lang (cookie), request.user.locale (user, or user(request)), Accept-Language (header, by its q), or functions of the request; else the fallback.
  • It is request.locale, and the locale of the async context of the request: i18n.t() without a locale speaks it in whatever the handler calls, after awaits too. i18n.run(locale, fn) does the same out of requests (jobs, emails).
  • The answers say Content-Language (and Vary: Accept-Language when the header chose it); contentLanguage: false leaves them alone.

The messages of the ORM

import * as orm from '@xufa/orm';
i18n.translateOrm(orm); // the validation of the ORM speaks the locale of each request

// POST /books with Accept-Language: es
// 400 { errors: { title: ['Este campo es obligatorio.'], pages: ['Asegúrate de que este valor sea mayor o igual que 1.'] } }
  • xufa translates the messages of the ORM into es, fr, de, pt and it, under orm.* (orm.required, orm.maxLength...); a catalog of the app goes over them, and other languages get English.
  • The messages of rules of your own can be keys of the catalogs: validate: { rule: 'value > 0', message: 'books.pages.positive' } is translated; any other text stays as it is.

Logins, accounts and the admin

import * as auth from '@xufa/auth';
import * as admin from '@xufa/admin';
i18n.translateAuth(auth).translateAdmin(admin);

// POST /account/login with Accept-Language: es and a wrong password
// 401 { error: 'Email o contraseña incorrectos' }
  • translateAuth(auth): what users read of @xufa/auth, under auth.*: the answers of logins (auth.invalid, auth.throttled, auth.code...), the policy of passwords (auth.tooShort with {min}), authenticator apps and recovery codes, the routes of auth.accounts, and the emails of its links (auth.resetSubject, auth.resetBody...), in the language of the request that asked for them.
  • translateAdmin(admin): the errors of the API of the admin that its page shows, under admin.* (admin.readOnly with {model}, admin.forbidden with {permission}...); its login and account page are those of translateAuth.
  • Both bundle es, fr, de, pt and it; the app's catalogs go over them ({ de: { auth: { invalidEmail: '...' } } }), and other languages get English. The keys and their English are auth.AUTH_MESSAGES and admin.ADMIN_MESSAGES. The errors of a wrong setup stay in English: they are for the developer.
  • Each module has one translator (setTranslator(fn | null)), as the ORM: i18n.install(module, namespace, catalogs) does the same for a module of your own.
