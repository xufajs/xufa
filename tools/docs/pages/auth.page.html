Auth

@xufa/auth is the authentication of xufa: logins with passwords, JSON Web Tokens, refresh tokens, one-time codes, API keys and who may use each route, for @xufa/http. No dependencies: everything is node:crypto.

3routes made for you: login, refresh and logout
1option on a route says who may use it: config: { auth: ['admin'] }
0dependencies

Install

npm install @xufa/auth   # or: npm install xufa, and require('xufa/auth')

An app with logins

Users in a database of @xufa/orm (SQLite in memory here), the routes of login, and two routes for users and for admins:

const xufa = require('@xufa/http');
const { Database, Model, fields, plugin: orm } = require('@xufa/orm');
const auth = require('@xufa/auth');

class User extends Model {
  static fields = {
    email: fields.string({ unique: true }),
    password: fields.string(), // a hash of hashPassword()
    role: fields.string({ default: 'user' }),
  };
}
class RefreshToken extends Model {
  static fields = auth.refreshTokenFields(fields);
}

const db = new Database({ backend: 'sqlite', filename: ':memory:' });
db.register(User, RefreshToken);

const app = xufa();
app.register(orm, { database: db, sync: true });
app.register(auth.plugin, {
  keys: process.env.JWT_KEY, // signs the access tokens (a KeySet rotates them)
  login: {
    findUser: (email) => User.objects.filter({ email: email.toLowerCase() }).first(),
    claims: (user) => ({ sub: String(user.id), role: user.role }),
  },
  refresh: { store: auth.modelStore(RefreshToken), ttl: '30d' },
}); // POST /auth/login, /auth/refresh, /auth/logout
app.get('/me', { config: { auth: true } }, async (request) => ({ id: request.user.sub, role: request.user.role }));
app.get('/admin', { config: { auth: ['admin'] } }, async () => ({ secret: 42 }));
await app.ready();
await User.objects.create({ email: 'ada@example.com', password: await auth.hashPassword('correct horse') });

const login = await app.inject({
  method: 'POST',
  url: '/auth/login',
  payload: { username: 'ada@example.com', password: 'correct horse' },
});
const { accessToken, refreshToken } = login.json();
const bearer = { authorization: `Bearer ${accessToken}` };
console.log((await app.inject({ url: '/me', headers: bearer })).body);
console.log((await app.inject({ url: '/admin', headers: bearer })).statusCode); // a user, not an admin

const refresh = (token) => app.inject({ method: 'POST', url: '/auth/refresh', payload: { refreshToken: token } });
console.log((await refresh(refreshToken)).statusCode, (await refresh(refreshToken)).statusCode); // spent once used
await app.close();

The Guide goes on: one-time codes (TOTP), lockout after failures, keys that rotate and keys per tenant, API keys, cookies, the strategies of Passport, and each part used alone.

Why @xufa/auth

  • The routes, not only the parts. Login, refresh and logout are made by the plugin from two functions of yours (find a user, its claims); routes say who may use them in their config.
  • Safe defaults. scrypt with the parameters OWASP recommends (and a rehash when they change), access tokens of minutes and refresh tokens that rotate (a token used twice ends its family: a stolen one is found out), lockout after failed logins, identifiers normalized against look-alike characters (Unicode's confusables).
  • Tenants. Each tenant can have its own keys and users: a token of one is refused by the others.
  • Each part alone. Passwords, tokens, TOTP, lockout and API keys are functions of their own, for code that is not an app of xufa.
