@xufa/yaml

YAML 1.2 for Node.js with no dependencies: the code of js-yaml 4.1.0 and its test suite. @xufa/openapi reads and writes OpenAPI documents with it.

Quick start

npm install @xufa/yaml
const yaml = require('@xufa/yaml');

const doc = yaml.load(fs.readFileSync('openapi.yaml', 'utf8'));
const text = yaml.dump(doc, { noRefs: true, lineWidth: -1 });

Loading

load(text, { schema, filename, json, onWarning }) reads one document; loadAll(text) every document of a stream. Loading runs no code. The default schema has the types of YAML 1.2 and the ones of js-yaml (timestamps as dates, binary, sets, ordered maps, merge keys); CORE_SCHEMA, JSON_SCHEMA and FAILSAFE_SCHEMA have fewer (with CORE_SCHEMA, dates stay strings). Errors are YAMLExceptions with the line and column (mark) and a snippet of the text.

Writing

dump(value, options): indent, flowLevel, sortKeys, lineWidth (-1: no folding), noRefs (no anchors for objects used twice), quotingType, forceQuotes, replacer, skipInvalid.

Types of your own

const Point = new yaml.Type('!point', { kind: 'sequence', construct: ([x, y]) => ({ x, y }) });
const schema = yaml.DEFAULT_SCHEMA.extend([Point]);
yaml.load('at: !point [1, 2]', { schema }); // { at: { x: 1, y: 2 } }

Coming from js-yaml

require('js-yaml') can be replaced by require('@xufa/yaml'): it is js-yaml 4.1.0, and its documentation applies.

Tests

The suite of js-yaml (units, samples of loading and of load errors, the dumper, a fuzzy dumper with fast-check, and its issues), ported to vyntra by tools/port-yaml.

TypeScript

The declarations of @types/js-yaml 4.0.9, with types (the types of the default schema).
